SDL não é uma API completa

Um esquema de banco de dados descreve armazenamento, enquanto o GraphQL descreve um contrato voltado à aplicação. O SDL gerado não cria resolvers, autenticação, paginação, validação, mutações nem autorização em nível de campo. Trate-o como um primeiro rascunho estruturado.

Revise o mapeamento de tipos

Os tipos do SQLite não correspondem perfeitamente aos escalares do GraphQL. Datas podem ser armazenadas como texto ou números, decimais podem precisar de um escalar personalizado e dados binários exigem uma representação específica da aplicação. Renomeie campos técnicos do banco quando um nome de API mais claro for apropriado.

Nunca exponha automaticamente todas as tabelas do banco de dados. Selecione apenas os campos e as operações que os clientes devem acessar e aplique a autorização na camada da API.

Use os relacionamentos com critério

Chaves estrangeiras declaradas podem sugerir relacionamentos GraphQL, mas o comportamento dos resolvers depende da implementação do seu servidor. Considere agrupamento em lotes e paginação para evitar acessos aninhados caros ao banco de dados.
