Depuração ao vivo no Android

Edite ao vivo o banco de dados de um app Android sem reiniciar o app

Adicione um pequeno auxiliar apenas de depuração ao seu app e edite o banco de dados SQLite dele pelo navegador enquanto o app continua em execução.

Abrir o visualizador

O que você ganha

A edição ao vivo funciona como o Database Inspector do Android Studio, mas pelo seu navegador. O SQLite Viewer envia cada alteração a um pequeno ContentProvider dentro do seu app de depuração, que a executa no próprio banco de dados do app. O app continua em execução e nada precisa ser parado, copiado ou reiniciado.

Somente builds de depuração. O auxiliar permite que qualquer pessoa com acesso de depuração USB execute instruções de gravação no banco de dados, então registre-o apenas em src/debug e nunca o inclua em um build de release.

Configure

  1. Adicione a classe auxiliar. Baixe SqliteViewerProvider.kt (ou copie o código abaixo) para o módulo do seu app, por exemplo app/src/main/java/com/example/debughelper/. Altere a linha package para corresponder à pasta.
  2. Registre-o apenas para builds de depuração. Crie app/src/debug/AndroidManifest.xml com a entrada do provider abaixo. Como ela fica no conjunto de fontes debug, os builds de release nunca contêm a entrada e nada é exposto.
  3. Opcional: atualize as telas do Room. O Room só percebe alterações feitas pela própria conexão. Defina o hook afterWrite uma vez para que suas telas com LiveData e Flow sejam atualizadas logo após uma edição ao vivo.
  4. Execute o build de depuração. Instale o build de depuração no telefone e abra o app uma vez para que o Android registre o provider.
  5. Ative a edição ao vivo. No SQLite Viewer, escolha Android, conecte o telefone, abra o banco de dados do app e marque Edição ao vivo. Aparece um selo verde LIVE EDIT. A partir de agora, cada edição de linha, inserção, exclusão e instrução SQL que você executar também é aplicada ao app em execução.

Manifesto de depuração

<?xml version="1.0" encoding="utf-8"?>
<!-- src/debug/AndroidManifest.xml  (debug builds only) -->
<manifest xmlns:android="http://schemas.android.com/apk/res/android">
    <application>
        <provider
            android:name="com.example.debughelper.SqliteViewerProvider"
            android:authorities="${applicationId}.sqliteviewer"
            android:exported="true" />
    </application>
</manifest>

Hook opcional do Room

// In your Application class (optional, only if you use Room LiveData / Flow)
override fun onCreate() {
    super.onCreate()
    if (BuildConfig.DEBUG) {
        SqliteViewerProvider.afterWrite = {
            AppDatabase.getInstance(this).invalidationTracker.refreshVersionsAsync()
        }
    }
}

O auxiliar (SqliteViewerProvider.kt)

package com.example.debughelper // use any package, for example your app's own

import android.content.ContentProvider
import android.content.ContentValues
import android.database.Cursor
import android.database.sqlite.SQLiteDatabase
import android.net.Uri
import android.os.Bundle
import android.util.Base64
import org.json.JSONArray

/**
 * DEBUG BUILDS ONLY.
 *
 * Lets SQLite Viewer (https://sqliteviewer.codemasterlk.com) edit this app's databases
 * while the app keeps running. The class can live in src/main, but it is only registered
 * in src/debug/AndroidManifest.xml, so release builds never expose it.
 */
class SqliteViewerProvider : ContentProvider() {

    companion object {
        /** Optional: called after every successful live edit, e.g. to refresh Room observers. */
        @JvmStatic
        var afterWrite: (() -> Unit)? = null

        private val allowedStatement = Regex("""^(INSERT|UPDATE|DELETE|REPLACE|CREATE|DROP|ALTER)\b""", RegexOption.IGNORE_CASE)
        private val leadingNoise = Regex("""^(\s|--[^\n]*\n|/\*.*?\*/)*""", RegexOption.DOT_MATCHES_ALL)
        private val safeName = Regex("""^[A-Za-z0-9._-]+$""")
    }

    private val handles = HashMap<String, SQLiteDatabase>()

    override fun onCreate(): Boolean = true

    override fun call(method: String, arg: String?, extras: Bundle?): Bundle {
        val answer = try {
            when (method) {
                "ping" -> "OK:1"
                "batch" -> "OK:" + runBatch(extras?.getString("db"), arg)
                else -> "ERR:unknown method $method"
            }
        } catch (e: Throwable) {
            "ERR:" + (e.message ?: e.javaClass.simpleName).replace('\n', ' ')
        }
        return Bundle().apply { putString("r", answer) }
    }

    @Synchronized
    private fun database(name: String): SQLiteDatabase {
        handles[name]?.let { if (it.isOpen) return it }

        val file = context!!.getDatabasePath(name)
        require(file.exists()) { "database not found: $name" }

        return SQLiteDatabase.openDatabase(file.path, null, SQLiteDatabase.OPEN_READWRITE)
            .also { handles[name] = it }
    }

    private fun runBatch(name: String?, base64: String?): Int {
        require(name != null && safeName.matches(name)) { "invalid database name" }
        require(!base64.isNullOrEmpty()) { "no statements" }

        val statements = JSONArray(String(Base64.decode(base64, Base64.DEFAULT), Charsets.UTF_8))
        val db = database(name)

        db.beginTransaction()
        try {
            for (i in 0 until statements.length()) {
                val sql = statements.getString(i)
                require(allowedStatement.containsMatchIn(sql.replaceFirst(leadingNoise, ""))) {
                    "statement type not allowed"
                }
                db.execSQL(sql)
            }
            db.setTransactionSuccessful()
        } finally {
            db.endTransaction()
        }

        afterWrite?.invoke()
        return statements.length()
    }

    // Not used: the viewer talks to this provider only through call().
    override fun query(uri: Uri, projection: Array<String>?, selection: String?, selectionArgs: Array<String>?, sortOrder: String?): Cursor? = null
    override fun getType(uri: Uri): String? = null
    override fun insert(uri: Uri, values: ContentValues?): Uri? = null
    override fun delete(uri: Uri, selection: String?, selectionArgs: Array<String>?): Int = 0
    override fun update(uri: Uri, values: ContentValues?, selection: String?, selectionArgs: Array<String>?): Int = 0
}

O que ele pode e não pode fazer

  • Ele executa instruções INSERT, UPDATE, DELETE, REPLACE, CREATE, DROP e ALTER. Leituras, PRAGMAs e VACUUM são recusados.
  • Cada edição é aplicada em uma transação. Se o app a rejeitar, o SQLite Viewer mostra o erro e recarrega os dados do telefone para que ambos continuem sincronizados.
  • Edições muito grandes (cerca de 75 KB de SQL) não são enviadas ao vivo. Use Enviar para o telefone nesses casos. Isso substitui todo o arquivo do banco de dados e reinicia o app.
  • O nome do banco de dados deve corresponder ao arquivo na pasta databases do app. O auxiliar usa o nome do pacote do app de depuração, então também funciona com applicationIdSuffix.
  • Funciona com o Android Studio em execução ao mesmo tempo quando você usa o modo servidor ADB do painel Android (guia de configuração da ponte).

Solução de problemas

  • “Live-edit helper not found”: a entrada do manifesto de depuração está ausente, o app não foi reinstalado ou o nome do pacote é diferente. A authority do provider deve ser <seu pacote>.sqliteviewer.
  • “database not found”: abra o app uma vez para que ele crie seu banco de dados e tente novamente.
  • As telas não atualizam: adicione o hook opcional do Room acima ou reabra a tela.
