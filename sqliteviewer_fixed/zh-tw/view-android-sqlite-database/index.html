開啟 Android 資料庫

請先合法、安全地匯出資料庫

SQLite Viewer 開啟的是您已經擁有的檔案，不會從手機中擷取資料庫。請使用 Android Studio 的 Device Explorer、模擬器、應用程式備份或您自己的偵錯工具，來取得您有權檢視的資料庫。

Android 應用程式資料庫通常位於應用程式專屬的 databases 目錄下，可能使用 .db 副檔名或沒有副檔名。如果瀏覽器的檔案選擇器沒有顯示無副檔名的副本，請將匯出的檔案重新命名為以 .db 結尾。

開啟並檢視應用程式結構

  1. 將匯出的資料庫拖曳到 SQLite Viewer 上。
  2. 在資料表側邊欄中搜尋您正在偵錯的功能。
  3. 開啟可能相關的資料表並檢視最近的列。
  4. 使用 ER 圖了解外部索引鍵和 Room 風格的關聯。
  5. 執行有針對性的 SQL，而不是在龐大的事件資料表或快取資料表中捲動尋找。
SELECT *
FROM "sync_queue"
ORDER BY "created_at" DESC
LIMIT 0, 100;

透過 USB 即時檢視偵錯應用程式的資料庫

在桌面版 Chrome 或 Edge 中，選擇工具列中的 Android，連接已開啟 USB 偵錯的手機，並選擇您的某個可偵錯應用程式。SQLite Viewer 使用 run-as 複製資料庫，合併預寫記錄以包含最新的寫入，並可在您測試時每隔幾秒重新整理一次。一切都保留在瀏覽器中。發行版本受 Android 保護，無法以這種方式讀取。

Android Studio 會佔用 USB 連線，因此檢視器還提供 ADB 伺服器模式：在 Windows 上，下載一鍵式橋接安裝程式並按兩下執行一次。它會設定一個在每次登入時自動啟動的小型輔助程式，頁面與 Android Studio 共用 ADB 伺服器，因此兩者可同時運作。在 macOS 和 Linux 上，請改為執行 adb-bridge.py 輔助程式。頁面會自動偵測橋接程式。完整說明：ADB 橋接設定指南。

想在不重新啟動應用程式的情況下修改資料？新增一個僅用於偵錯的小型輔助程式，並依照即時編輯設定指南操作。

正確處理 WAL 資料庫

SQLite 可能使用預寫記錄，產生 -wal 和 -shm 配套檔案。在應用程式寫入時只複製主要資料庫，可能會遺漏最近的交易。建議使用在資料庫關閉或已檢查點後建立的一致性匯出。

敏感資料：應用程式資料庫可能包含個人資訊、權杖或業務記錄。請僅使用您有權檢視的檔案，並在偵錯完成後刪除匯出的副本。

編輯 Android 資料庫

您可以編輯副本並下載，但取代應用程式資料庫可能違反結構預期或破壞應用程式狀態。請保留原始檔案，驗證限制條件，並盡可能使用受支援的移轉或偵錯工具。
