Android डेटाबेसएडिटरव्यूअर खोलें

Android लाइव डीबगिंग

ऐप को रीस्टार्ट किए बिना Android ऐप डेटाबेस को लाइव संपादित करें

अपने ऐप में एक छोटा, केवल डीबग वाला सहायक जोड़ें और ऐप के चलते रहने के दौरान ब्राउज़र से उसका SQLite डेटाबेस संपादित करें।

व्यूअर खोलें

आपको क्या मिलता है

लाइव एडिट Android Studio के Database Inspector की तरह काम करता है, पर आपके ब्राउज़र से। SQLite Viewer हर बदलाव आपके डीबग ऐप के अंदर एक छोटे ContentProvider को भेजता है, जो उसे ऐप के अपने डेटाबेस पर चलाता है। ऐप चलता रहता है, और कुछ भी रोकना, कॉपी करना या रीस्टार्ट करना नहीं पड़ता।

केवल डीबग बिल्ड। यह सहायक USB डीबगिंग पहुँच रखने वाले किसी भी व्यक्ति को डेटाबेस पर राइट स्टेटमेंट चलाने देता है, इसलिए इसे केवल src/debug में रजिस्टर करें और कभी रिलीज़ बिल्ड में शामिल न करें।

इसे सेट अप करें

  1. सहायक क्लास जोड़ें। SqliteViewerProvider.kt डाउनलोड करें (या नीचे का कोड कॉपी करें) और उसे अपने ऐप मॉड्यूल में रखें, जैसे app/src/main/java/com/example/debughelper/। package लाइन को फ़ोल्डर के अनुसार बदलें।
  2. इसे केवल डीबग बिल्ड के लिए रजिस्टर करें। नीचे दी गई प्रोवाइडर एंट्री के साथ app/src/debug/AndroidManifest.xml बनाएँ। चूँकि यह debug सोर्स सेट में रहता है, रिलीज़ बिल्ड में यह एंट्री कभी नहीं होती और कुछ भी उजागर नहीं होता।
  3. वैकल्पिक: Room स्क्रीन रीफ़्रेश करें। Room केवल अपने कनेक्शन से किए गए बदलाव पहचानता है। afterWrite हुक एक बार सेट करें ताकि आपकी LiveData और Flow स्क्रीन लाइव एडिट के तुरंत बाद अपडेट हों।
  4. डीबग बिल्ड चलाएँ। अपना डीबग बिल्ड फ़ोन पर इंस्टॉल करें और ऐप एक बार खोलें ताकि Android प्रोवाइडर रजिस्टर कर ले।
  5. लाइव एडिट चालू करें। SQLite Viewer में Android चुनें, अपना फ़ोन कनेक्ट करें, ऐप का डेटाबेस खोलें और लाइव एडिट पर टिक करें। एक हरा LIVE EDIT बैज दिखता है। अब आपका हर पंक्ति संपादन, इन्सर्ट, डिलीट और SQL स्टेटमेंट चल रहे ऐप पर भी लागू होता है।

डीबग मैनिफ़ेस्ट

<?xml version="1.0" encoding="utf-8"?>
<!-- src/debug/AndroidManifest.xml  (debug builds only) -->
<manifest xmlns:android="http://schemas.android.com/apk/res/android">
    <application>
        <provider
            android:name="com.example.debughelper.SqliteViewerProvider"
            android:authorities="${applicationId}.sqliteviewer"
            android:exported="true" />
    </application>
</manifest>

वैकल्पिक Room हुक

override fun onCreate() {
    super.onCreate()
    if (BuildConfig.DEBUG) {
        SqliteViewerProvider.afterWrite = {
            AppDatabase.getInstance(this).invalidationTracker.refreshVersionsAsync()
        }
    }

सहायक (SqliteViewerProvider.kt)

package com.example.debughelper // use any package, for example your app's own

import android.content.ContentProvider
import android.content.ContentValues
import android.database.Cursor
import android.database.sqlite.SQLiteDatabase
import android.net.Uri
import android.os.Bundle
import android.util.Base64
import org.json.JSONArray

/**
 * DEBUG BUILDS ONLY.
 *
 * Lets SQLite Viewer (https://sqliteviewer.codemasterlk.com) edit this app's databases
 * while the app keeps running. The class can live in src/main, but it is only registered
 * in src/debug/AndroidManifest.xml, so release builds never expose it.
 */
class SqliteViewerProvider : ContentProvider() {

    companion object {
        /** Optional: called after every successful live edit, e.g. to refresh Room observers. */
        @JvmStatic
        var afterWrite: (() -> Unit)? = null

        private val allowedStatement = Regex("""^(INSERT|UPDATE|DELETE|REPLACE|CREATE|DROP|ALTER)\b""", RegexOption.IGNORE_CASE)
        private val leadingNoise = Regex("""^(\s|--[^\n]*\n|/\*.*?\*/)*""", RegexOption.DOT_MATCHES_ALL)
        private val safeName = Regex("""^[A-Za-z0-9._-]+$""")
    }

    private val handles = HashMap<String, SQLiteDatabase>()

    override fun onCreate(): Boolean = true

    override fun call(method: String, arg: String?, extras: Bundle?): Bundle {
        val answer = try {
            when (method) {
                "ping" -> "OK:1"
                "batch" -> "OK:" + runBatch(extras?.getString("db"), arg)
                else -> "ERR:unknown method $method"
            }
        } catch (e: Throwable) {
            "ERR:" + (e.message ?: e.javaClass.simpleName).replace('\n', ' ')
        }
        return Bundle().apply { putString("r", answer) }
    }

    @Synchronized
    private fun database(name: String): SQLiteDatabase {
        handles[name]?.let { if (it.isOpen) return it }

        val file = context!!.getDatabasePath(name)
        require(file.exists()) { "database not found: $name" }

        return SQLiteDatabase.openDatabase(file.path, null, SQLiteDatabase.OPEN_READWRITE)
            .also { handles[name] = it }
    }

    private fun runBatch(name: String?, base64: String?): Int {
        require(name != null && safeName.matches(name)) { "invalid database name" }
        require(!base64.isNullOrEmpty()) { "no statements" }

        val statements = JSONArray(String(Base64.decode(base64, Base64.DEFAULT), Charsets.UTF_8))
        val db = database(name)

        db.beginTransaction()
        try {
            for (i in 0 until statements.length()) {
                val sql = statements.getString(i)
                require(allowedStatement.containsMatchIn(sql.replaceFirst(leadingNoise, ""))) {
                    "statement type not allowed"
                }
                db.execSQL(sql)
            }
            db.setTransactionSuccessful()
        } finally {
            db.endTransaction()
        }

        afterWrite?.invoke()
        return statements.length()
    }

    // Not used: the viewer talks to this provider only through call().
    override fun query(uri: Uri, projection: Array<String>?, selection: String?, selectionArgs: Array<String>?, sortOrder: String?): Cursor? = null
    override fun getType(uri: Uri): String? = null
    override fun insert(uri: Uri, values: ContentValues?): Uri? = null
    override fun delete(uri: Uri, selection: String?, selectionArgs: Array<String>?): Int = 0
    override fun update(uri: Uri, values: ContentValues?, selection: String?, selectionArgs: Array<String>?): Int = 0
}

यह क्या कर सकता है और क्या नहीं

  • यह INSERT, UPDATE, DELETE, REPLACE, CREATE, DROP और ALTER स्टेटमेंट चलाता है। रीड, PRAGMA और VACUUM अस्वीकार किए जाते हैं।
  • हर संपादन एक ट्रांज़ैक्शन में लागू होता है। अगर ऐप उसे अस्वीकार करता है, तो SQLite Viewer त्रुटि दिखाता है और फ़ोन से डेटा दोबारा लोड करता है ताकि दोनों सिंक में रहें।
  • बहुत बड़े संपादन (लगभग 75 KB SQL) लाइव नहीं भेजे जाते। उनके लिए फ़ोन पर पुश करें इस्तेमाल करें। यह पूरी डेटाबेस फ़ाइल बदल देता है और ऐप रीस्टार्ट करता है।
  • डेटाबेस का नाम ऐप के databases फ़ोल्डर की फ़ाइल से मेल खाना चाहिए। सहायक डीबग ऐप का पैकेज नाम इस्तेमाल करता है, इसलिए applicationIdSuffix के साथ भी काम करता है।
  • जब आप Android पैनल का ADB सर्वर मोड इस्तेमाल करते हैं, तो यह Android Studio के साथ एक ही समय पर चल सकता है (ब्रिज सेटअप गाइड)।

समस्या निवारण

  • “Live-edit helper not found”: डीबग मैनिफ़ेस्ट एंट्री गायब है, ऐप दोबारा इंस्टॉल नहीं हुआ, या पैकेज नाम अलग है। प्रोवाइडर authority <आपका पैकेज>.sqliteviewer होनी चाहिए।
  • “database not found”: ऐप एक बार खोलें ताकि वह अपना डेटाबेस बना ले, फिर दोबारा कोशिश करें।
  • स्क्रीन अपडेट नहीं होतीं: ऊपर दिया वैकल्पिक Room हुक जोड़ें, या स्क्रीन दोबारा खोलें।
