API स्कीमा की शुरुआत

SQLite को GraphQL SDL में बदलें

डेटाबेस एंटिटी को पढ़ने योग्य GraphQL टाइप परिभाषाओं में बदलें, फिर उन्हें अपने ऐप की ज़रूरत के अनुसार ढालें।

GraphQL SDL एक्सपोर्टर खोलें

स्कीमा बनाएँ

  1. SQLite डेटाबेस खोलें।
  2. ER डायग्राम में इसकी एंटिटी देखें।
  3. एक्सपोर्ट फ़ॉर्मैट के रूप में GraphQL SDL चुनें।
  4. टाइप परिभाषाएँ एक्सपोर्ट करें और अपने API प्रोजेक्ट में देखें।
type Customer {
  id: Int!
  name: String
  orders: [Order!]
}

type Order {
  id: Int!
  customerId: Int!
}

SDL पूरा API नहीं है

डेटाबेस स्कीमा स्टोरेज का वर्णन करता है, जबकि GraphQL ऐप के सामने वाले अनुबंध का। बनाया गया SDL रिज़ॉल्वर, ऑथेंटिकेशन, पेजिनेशन, वैलिडेशन, म्यूटेशन या फ़ील्ड-स्तर का प्राधिकरण नहीं बनाता। इसे संरचित पहला मसौदा मानें।

टाइप मैपिंग की समीक्षा करें

SQLite टाइप GraphQL स्केलर से पूरी तरह मेल नहीं खाते। तारीखें टेक्स्ट या संख्या के रूप में संग्रहीत हो सकती हैं, दशमलव के लिए कस्टम स्केलर चाहिए हो सकता है, और बाइनरी डेटा को ऐप-विशिष्ट प्रस्तुति चाहिए। जब API के लिए ज़्यादा स्पष्ट नाम उपयुक्त हो, तो तकनीकी डेटाबेस फ़ील्ड का नाम बदलें।

हर डेटाबेस टेबल को अपने-आप कभी उजागर न करें। केवल वे फ़ील्ड और ऑपरेशन चुनें जिन तक क्लाइंट की पहुँच होनी चाहिए, फिर API लेयर में प्राधिकरण लागू करें।

संबंधों का सोच-समझकर उपयोग करें

घोषित फ़ॉरेन-की GraphQL संबंध सुझा सकती हैं, पर रिज़ॉल्वर का व्यवहार आपके सर्वर कार्यान्वयन पर निर्भर करता है। महँगी नेस्टेड डेटाबेस पहुँच से बचने के लिए बैचिंग और पेजिनेशन पर विचार करें।
