Guide des requêtes SQLite

Requêtes utiles pour inspecter des bases SQLite

Commencez par du SQL sûr et ciblé lorsque vous devez comprendre les tables, les index, les relations et la qualité des données.

Ouvrir l'espace SQL

Lister les tables et vues utilisateur

SELECT type, name, sql
FROM sqlite_master
WHERE type IN ('table', 'view')
  AND name NOT LIKE 'sqlite_%'
ORDER BY type, name;

Inspecter les colonnes d'une table

PRAGMA table_info('orders');

Cela renvoie le type déclaré, la possibilité de valeur nulle, la valeur par défaut et la position dans la clé primaire de chaque colonne.

Examiner les clés étrangères

PRAGMA foreign_key_list('orders');
PRAGMA foreign_key_check;

La première instruction décrit les références déclarées d'une table. La seconde signale les lignes qui violent les relations de clés étrangères activées.

Trouver les valeurs en double

SELECT email, COUNT(*) AS occurrences
FROM customers
WHERE email IS NOT NULL
GROUP BY email
HAVING COUNT(*) > 1
ORDER BY occurrences DESC;

Inspecter les index

PRAGMA index_list('orders');

Après avoir trouvé le nom d'un index, inspectez ses colonnes avec PRAGMA index_info('nom_index').

Vérifier le comportement d'une requête

EXPLAIN QUERY PLAN
SELECT *
FROM orders
WHERE customer_id = 42
ORDER BY created_at DESC;

Le plan peut révéler des parcours complets de table et indiquer si SQLite peut utiliser un index pertinent.

Méthode sûre : commencez par des requêtes d'inspection SELECT ou PRAGMA. Avant un UPDATE ou un DELETE, exécutez un SELECT avec la même condition WHERE et conservez une copie d'origine de la base.

Paginer de grandes tables

SELECT *
FROM events
ORDER BY id
LIMIT 100 OFFSET 0;

Pour naviguer à répétition dans de très grandes tables, la pagination par clé, telle que WHERE id > ? ORDER BY id LIMIT 100, est souvent plus efficace qu'un très grand décalage.
