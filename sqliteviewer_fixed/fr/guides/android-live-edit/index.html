Débogage Android en direct

Modifier en direct la base d'une application Android sans redémarrer l'application

Ajoutez un petit assistant réservé au débogage à votre application et modifiez sa base SQLite depuis le navigateur pendant qu'elle continue de tourner.

Ouvrir la visionneuse

Ce que vous obtenez

L'édition en direct fonctionne comme le Database Inspector d'Android Studio, mais depuis votre navigateur. SQLite Viewer envoie chaque modification à un petit ContentProvider intégré à votre application de débogage, qui l'exécute sur la base de l'application elle-même. L'application continue de tourner et rien n'a besoin d'être arrêté, copié ou redémarré.

Versions de débogage uniquement. L'assistant permet à toute personne ayant un accès de débogage USB d'exécuter des instructions d'écriture sur la base ; enregistrez-le donc uniquement dans src/debug et ne l'incluez jamais dans une version de production.

Mise en place

  1. Ajoutez la classe assistante. Téléchargez SqliteViewerProvider.kt (ou copiez le code ci-dessous) dans le module de votre application, par exemple app/src/main/java/com/example/debughelper/. Modifiez la ligne package pour qu'elle corresponde au dossier.
  2. Enregistrez-le uniquement pour les versions de débogage. Créez app/src/debug/AndroidManifest.xml avec l'entrée de fournisseur ci-dessous. Comme elle se trouve dans le jeu de sources debug, les versions de production ne contiennent jamais l'entrée et rien n'est exposé.
  3. Facultatif : actualisez les écrans Room. Room ne remarque que les modifications faites via sa propre connexion. Définissez une fois le hook afterWrite pour que vos écrans LiveData et Flow se mettent à jour juste après une édition en direct.
  4. Lancez la version de débogage. Installez votre version de débogage sur le téléphone et ouvrez l'application une fois pour qu'Android enregistre le fournisseur.
  5. Activez l'édition en direct. Dans SQLite Viewer, choisissez Android, connectez votre téléphone, ouvrez la base de l'application et cochez Édition en direct. Un badge vert LIVE EDIT apparaît. Désormais, chaque modification de ligne, insertion, suppression et instruction SQL que vous exécutez est aussi appliquée à l'application en cours d'exécution.

Manifeste de débogage

<?xml version="1.0" encoding="utf-8"?>
<!-- src/debug/AndroidManifest.xml  (debug builds only) -->
<manifest xmlns:android="http://schemas.android.com/apk/res/android">
    <application>
        <provider
            android:name="com.example.debughelper.SqliteViewerProvider"
            android:authorities="${applicationId}.sqliteviewer"
            android:exported="true" />
    </application>
</manifest>

Hook Room facultatif

// In your Application class (optional, only if you use Room LiveData / Flow)
override fun onCreate() {
    super.onCreate()
    if (BuildConfig.DEBUG) {
        SqliteViewerProvider.afterWrite = {
            AppDatabase.getInstance(this).invalidationTracker.refreshVersionsAsync()
        }
    }
}

L'assistant (SqliteViewerProvider.kt)

package com.example.debughelper // use any package, for example your app's own

import android.content.ContentProvider
import android.content.ContentValues
import android.database.Cursor
import android.database.sqlite.SQLiteDatabase
import android.net.Uri
import android.os.Bundle
import android.util.Base64
import org.json.JSONArray

/**
 * DEBUG BUILDS ONLY.
 *
 * Lets SQLite Viewer (https://sqliteviewer.codemasterlk.com) edit this app's databases
 * while the app keeps running. The class can live in src/main, but it is only registered
 * in src/debug/AndroidManifest.xml, so release builds never expose it.
 */
class SqliteViewerProvider : ContentProvider() {

    companion object {
        /** Optional: called after every successful live edit, e.g. to refresh Room observers. */
        @JvmStatic
        var afterWrite: (() -> Unit)? = null

        private val allowedStatement = Regex("""^(INSERT|UPDATE|DELETE|REPLACE|CREATE|DROP|ALTER)\b""", RegexOption.IGNORE_CASE)
        private val leadingNoise = Regex("""^(\s|--[^\n]*\n|/\*.*?\*/)*""", RegexOption.DOT_MATCHES_ALL)
        private val safeName = Regex("""^[A-Za-z0-9._-]+$""")
    }

    private val handles = HashMap<String, SQLiteDatabase>()

    override fun onCreate(): Boolean = true

    override fun call(method: String, arg: String?, extras: Bundle?): Bundle {
        val answer = try {
            when (method) {
                "ping" -> "OK:1"
                "batch" -> "OK:" + runBatch(extras?.getString("db"), arg)
                else -> "ERR:unknown method $method"
            }
        } catch (e: Throwable) {
            "ERR:" + (e.message ?: e.javaClass.simpleName).replace('\n', ' ')
        }
        return Bundle().apply { putString("r", answer) }
    }

    @Synchronized
    private fun database(name: String): SQLiteDatabase {
        handles[name]?.let { if (it.isOpen) return it }

        val file = context!!.getDatabasePath(name)
        require(file.exists()) { "database not found: $name" }

        return SQLiteDatabase.openDatabase(file.path, null, SQLiteDatabase.OPEN_READWRITE)
            .also { handles[name] = it }
    }

    private fun runBatch(name: String?, base64: String?): Int {
        require(name != null && safeName.matches(name)) { "invalid database name" }
        require(!base64.isNullOrEmpty()) { "no statements" }

        val statements = JSONArray(String(Base64.decode(base64, Base64.DEFAULT), Charsets.UTF_8))
        val db = database(name)

        db.beginTransaction()
        try {
            for (i in 0 until statements.length()) {
                val sql = statements.getString(i)
                require(allowedStatement.containsMatchIn(sql.replaceFirst(leadingNoise, ""))) {
                    "statement type not allowed"
                }
                db.execSQL(sql)
            }
            db.setTransactionSuccessful()
        } finally {
            db.endTransaction()
        }

        afterWrite?.invoke()
        return statements.length()
    }

    // Not used: the viewer talks to this provider only through call().
    override fun query(uri: Uri, projection: Array<String>?, selection: String?, selectionArgs: Array<String>?, sortOrder: String?): Cursor? = null
    override fun getType(uri: Uri): String? = null
    override fun insert(uri: Uri, values: ContentValues?): Uri? = null
    override fun delete(uri: Uri, selection: String?, selectionArgs: Array<String>?): Int = 0
    override fun update(uri: Uri, values: ContentValues?, selection: String?, selectionArgs: Array<String>?): Int = 0
}

Ce qu'il peut et ne peut pas faire

  • Il exécute des instructions INSERT, UPDATE, DELETE, REPLACE, CREATE, DROP et ALTER. Les lectures, les PRAGMA et VACUUM sont refusés.
  • Chaque modification est appliquée dans une transaction. Si l'application la rejette, SQLite Viewer affiche l'erreur et recharge les données depuis le téléphone pour que les deux restent synchronisés.
  • Les très grosses modifications (environ 75 Ko de SQL) ne sont pas envoyées en direct. Utilisez Envoyer vers le téléphone pour celles-ci. Cela remplace tout le fichier de base de données et redémarre l'application.
  • Le nom de la base doit correspondre au fichier du dossier databases de l'application. L'assistant utilise le nom de package de l'application de débogage, il fonctionne donc aussi avec applicationIdSuffix.
  • Fonctionne avec Android Studio lancé en même temps lorsque vous utilisez le mode serveur ADB du panneau Android (guide de configuration du pont).

Dépannage

  • « Live-edit helper not found » : l'entrée du manifeste de débogage est absente, l'application n'a pas été réinstallée ou le nom du package diffère. L'authority du fournisseur doit être <votre package>.sqliteviewer.
  • « database not found » : ouvrez l'application une fois pour qu'elle crée sa base de données, puis réessayez.
  • Les écrans ne se mettent pas à jour : ajoutez le hook Room facultatif ci-dessus ou rouvrez l'écran.
