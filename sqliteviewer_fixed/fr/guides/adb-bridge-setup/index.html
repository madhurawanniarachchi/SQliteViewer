Débogage Android en direct

Configurer le pont ADB (fonctionne avec Android Studio)

Un petit assistant permet à SQLite Viewer et à Android Studio d'utiliser votre téléphone en même temps. Téléchargez-le, placez-le, faites-le démarrer tout seul, et c'est terminé.

Ouvrir la visionneuse

Ai-je besoin du pont ?

Souvent non. SQLite Viewer peut communiquer directement avec votre téléphone en USB (mode USB direct dans Chrome ou Edge), sans rien installer. Le pont sert dans un seul cas : Android Studio (ou un autre outil ADB) utilise déjà le téléphone. Un seul programme peut posséder la connexion USB ; le pont permet donc à SQLite Viewer de partager le serveur ADB d'Android Studio. Les deux fonctionnent alors en même temps.

Windows : installateur en un clic

  1. Téléchargez l'installateur. Dans SQLite Viewer, ouvrez Live Android, choisissez Serveur ADB et cliquez sur Télécharger l'installateur (Windows).
  2. Conservez le fichier. Chrome peut indiquer que le fichier ne peut pas être vérifié. Choisissez Conserver (ou Télécharger le fichier non vérifié). Le fichier est du texte brut ; vous pouvez donc l'ouvrir dans le Bloc-notes pour lire exactement ce qu'il fait.
  3. Exécutez-le une fois. Double-cliquez sur Install-ADB-Bridge.cmd. Si Windows affiche Windows a protégé votre ordinateur, cliquez sur Informations complémentaires, puis sur Exécuter quand même.
  4. Revenez à la page. L'installateur crée le pont sur votre PC, le fait démarrer tout seul à chaque ouverture de session et le lance. SQLite Viewer le détecte en quelques secondes. Cliquez sur Se connecter via le pont.

Le pont est installé dans %LOCALAPPDATA%\SQLiteViewerBridge et un raccourci dans votre dossier Démarrage le lance à l'ouverture de session. Pour le supprimer, exécutez uninstall.cmd depuis ce dossier.

Tout système : configuration avec Python

  1. Installez Python 3. Téléchargez-le sur python.org. Sous Windows, cochez Add Python to PATH dans l'installateur. La plupart des systèmes Linux ont déjà python3. macOS ne l'inclut pas par défaut : la première fois que vous tapez python3, macOS propose d'installer les Command Line Tools d'Apple (acceptez), ou vous pouvez utiliser l'installateur de python.org.
  2. Téléchargez le fichier. Téléchargez adb-bridge.py. Votre navigateur l'enregistre dans le dossier Téléchargements. S'il se termine par .txt, renommez-le en adb-bridge.py.
  3. Copiez-le à son emplacement définitif. Ouvrez un terminal (n'importe quel dossier convient, les commandes utilisent des chemins complets) et exécutez la commande de votre système. Elle crée le dossier et y copie le fichier. Si votre navigateur a enregistré le fichier ailleurs que dans Téléchargements, modifiez cette partie de la commande.
  4. Faites-le démarrer tout seul. Exécutez la commande de votre système. Elle configure l'entrée de démarrage à l'ouverture de session pour le fichier là où vous l'avez copié, et lance le pont maintenant.
  5. Connectez-vous. Retournez dans SQLite Viewer. Il trouve le pont tout seul. Cliquez sur Se connecter via le pont.

Étape 3 : copiez le fichier (à exécuter une fois)

Windows (PowerShell ; appuyez sur la touche Windows, tapez powershell, appuyez sur Entrée) :

New-Item -ItemType Directory -Force "$env:LOCALAPPDATA\SQLiteViewerBridgePython" | Out-Null; Copy-Item "$env:USERPROFILE\Downloads\adb-bridge.py" "$env:LOCALAPPDATA\SQLiteViewerBridgePython\adb-bridge.py"

Windows (Invite de commandes ; appuyez sur la touche Windows, tapez cmd, appuyez sur Entrée) :

mkdir "%LOCALAPPDATA%\SQLiteViewerBridgePython" & copy "%USERPROFILE%\Downloads\adb-bridge.py" "%LOCALAPPDATA%\SQLiteViewerBridgePython\adb-bridge.py"

macOS (Terminal) :

mkdir -p "$HOME/Library/Application Support/SQLiteViewerBridge" && cp "$HOME/Downloads/adb-bridge.py" "$HOME/Library/Application Support/SQLiteViewerBridge/adb-bridge.py"

Linux :

mkdir -p "$HOME/.local/share/sqliteviewer-bridge" && cp "$HOME/Downloads/adb-bridge.py" "$HOME/.local/share/sqliteviewer-bridge/adb-bridge.py"

Étape 4 : faites-le démarrer tout seul à l'ouverture de session (à exécuter une fois)

Windows (PowerShell) :

python "$env:LOCALAPPDATA\SQLiteViewerBridgePython\adb-bridge.py" --add-to-startup

Windows (Invite de commandes) :

python "%LOCALAPPDATA%\SQLiteViewerBridgePython\adb-bridge.py" --add-to-startup

macOS :

python3 "$HOME/Library/Application Support/SQLiteViewerBridge/adb-bridge.py" --add-to-startup

Linux :

python3 "$HOME/.local/share/sqliteviewer-bridge/adb-bridge.py" --add-to-startup

Sous Windows, cela crée un raccourci masqué dans votre dossier Démarrage ; sous macOS, un Launch Agent ; sous Linux, un service utilisateur systemd (ou une entrée de démarrage automatique du bureau). Aucun ne nécessite de droits d'administrateur. Laissez le fichier où il est ; si vous le déplacez, exécutez de nouveau la commande.

Pressé ? Une commande fait les étapes 3 et 4

Ouvrez un terminal dans le dossier où vous avez téléchargé le fichier et exécutez :

python adb-bridge.py --install      # Windows
python3 adb-bridge.py --install     # macOS and Linux

Vous préférez l'ajouter à Démarrage à la main ?

Windows : appuyez sur Win + R, tapez shell:startup et appuyez sur Entrée. Dans le dossier qui s'ouvre, faites un clic droit, choisissez Nouveau → Raccourci et définissez l'emplacement sur :

pythonw "%LOCALAPPDATA%\SQLiteViewerBridgePython\adb-bridge.py"

Nommez-le SQLite Viewer ADB Bridge. Utiliser pythonw au lieu de python évite la fenêtre noire. Déconnectez-vous puis reconnectez-vous, ou double-cliquez sur le raccourci pour le lancer maintenant.

macOS : la commande ci-dessus crée ~/Library/LaunchAgents/com.sqliteviewer.adbbridge.plist. Linux : elle crée ~/.config/systemd/user/sqliteviewer-bridge.service (ou ~/.config/autostart/sqliteviewer-bridge.desktop). Il est possible d'écrire ces fichiers à la main, mais la commande est plus sûre.

Vérifier, arrêter et supprimer

python adb-bridge.py --status                  # is it running?
python adb-bridge.py --remove-from-startup      # stop starting at sign-in (keeps the file)
python adb-bridge.py --uninstall                # stop it and delete everything
# add the full path to the file if you are not in its folder, as in the commands above

Ai-je ADB ? L'installer sinon

Le pont relaie vers ADB (Android Platform Tools). Android Studio l'inclut déjà ; si vous utilisez Android Studio, vous pouvez donc passer cette section. Pour vérifier, ouvrez un terminal et exécutez adb version. Si le système ne connaît pas la commande, installez ADB avec l'une des commandes ci-dessous. SQLite Viewer vous prévient aussi lorsque le pont fonctionne mais ne trouve pas ADB. Le pont cherche ADB dans votre PATH et dans les dossiers habituels d'Android Studio, de winget, de Homebrew et des téléchargements manuels ; vous n'avez donc pas besoin de modifier le PATH, et il démarre le serveur ADB pour vous.

Windows

Le plus simple (Windows 10 et 11, PowerShell ou Invite de commandes) :

winget install --id Google.PlatformTools -e

Pas de winget ? Téléchargez-le directement (PowerShell) :

Invoke-WebRequest https://dl.google.com/android/repository/platform-tools-latest-windows.zip -OutFile "$env:TEMP\pt.zip"; Expand-Archive "$env:TEMP\pt.zip" "$env:LOCALAPPDATA\Android\Sdk" -Force; Remove-Item "$env:TEMP\pt.zip"

La même chose dans l'Invite de commandes :

powershell -NoProfile -Command "Invoke-WebRequest https://dl.google.com/android/repository/platform-tools-latest-windows.zip -OutFile \"$env:TEMP\pt.zip\"; Expand-Archive \"$env:TEMP\pt.zip\" \"$env:LOCALAPPDATA\Android\Sdk\" -Force; Remove-Item \"$env:TEMP\pt.zip\""

Vérifiez que ça a marché (PowerShell) :

& "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe" version

macOS

Avec Homebrew :

brew install --cask android-platform-tools

Sans Homebrew :

mkdir -p "$HOME/Library/Android/sdk" && curl -L -o /tmp/pt.zip https://dl.google.com/android/repository/platform-tools-latest-darwin.zip && unzip -o /tmp/pt.zip -d "$HOME/Library/Android/sdk" && rm /tmp/pt.zip

Linux

Debian, Ubuntu, Mint :

sudo apt install adb

Fedora :

sudo dnf install android-tools

Arch, Manjaro :

sudo pacman -S android-tools

Toute autre distribution :

mkdir -p "$HOME/Android/Sdk" && curl -L -o /tmp/pt.zip https://dl.google.com/android/repository/platform-tools-latest-linux.zip && unzip -o /tmp/pt.zip -d "$HOME/Android/Sdk" && rm /tmp/pt.zip

Préparez ensuite le téléphone

  1. Sur le téléphone, ouvrez Paramètres → À propos du téléphone et appuyez sept fois sur Numéro de build.
  2. Ouvrez Paramètres → Options pour les développeurs et activez le Débogage USB.
  3. Branchez le téléphone et appuyez sur Autoriser dans la fenêtre qui s'affiche. L'exécution de adb devices doit l'afficher comme device.

Dois-je configurer quelque chose ?

Non. Le pont n'accepte que les connexions du site web SQLite Viewer, n'écoute que sur votre propre ordinateur (127.0.0.1) et ne relaie que vers le serveur ADB du même ordinateur. Rien n'est stocké ni envoyé ailleurs.

Vous n'avez besoin d'un réglage que dans deux cas :

  • Vous utilisez SQLite Viewer depuis une autre adresse (votre propre copie, ou localhost pendant le développement). Autorisez cette adresse dans les mêmes commandes :
python "%LOCALAPPDATA%\SQLiteViewerBridgePython\adb-bridge.py" --add-to-startup --allow-origin https://your-address.example
  • Le port 5038 est déjà utilisé. Utilisez un autre port, puis saisissez le même port dans Avancé du panneau Android :
python "%LOCALAPPDATA%\SQLiteViewerBridgePython\adb-bridge.py" --add-to-startup --port 5040

Les adresses autorisées sont mémorisées dans un fichier nommé origins.txt (une adresse par ligne) à côté du pont : sous Windows %LOCALAPPDATA%\SQLiteViewerBridge (installateur) ou %LOCALAPPDATA%\SQLiteViewerBridgePython (Python), sous macOS ~/Library/Application Support/SQLiteViewerBridge, sous Linux ~/.local/share/sqliteviewer-bridge.

Dépannage

  • « The bridge is not running on this computer » : exécutez l'installateur ou les commandes ci-dessus, ou déconnectez-vous puis reconnectez-vous. Rouvrez ensuite le panneau Android.
  • Je n'ai pas Python : sous Windows, vous n'en avez pas besoin, utilisez l'installateur en un clic ci-dessus. Sinon, installez Python 3 depuis python.org (Windows : cochez Add Python to PATH) ou, sous macOS, acceptez la proposition d'installer les Command Line Tools. Exécutez ensuite de nouveau les commandes.
  • python n'est pas reconnu, ou ouvre le Microsoft Store (Windows) : Python n'est pas encore installé, ou l'option PATH a été oubliée. Installez-le depuis python.org, ou remplacez python par py dans les commandes. Vous pouvez aussi désactiver le raccourci du Store dans Paramètres → Applications → Paramètres avancés des applications → Alias d'exécution d'application.
  • La commande de copie indique que le fichier est introuvable : votre navigateur a enregistré adb-bridge.py ailleurs que dans Téléchargements. Modifiez cette partie de la commande, ou renommez un fichier .txt.
  • « Something is already listening on port 5038 » : un autre pont est en cours d'exécution. Supprimez l'ancien (--uninstall ou uninstall.cmd) ou choisissez un autre port avec --port.
  • Le pont fonctionne mais aucun téléphone n'apparaît : le serveur ADB doit voir le téléphone. Exécutez adb devices, activez le débogage USB et acceptez l'invite « Autoriser le débogage USB » sur le téléphone.
  • « The bridge is running, but ADB is not installed » : installez ADB avec les commandes de la section Ai-je ADB ? ci-dessus (ou installez Android Studio). La page le détecte d'elle-même quelques secondes plus tard.
  • Chrome demande d'autoriser l'accès aux appareils de votre réseau : autorisez. C'est ainsi que la page atteint le pont sur votre propre ordinateur.
  • L'antivirus ou Windows bloque l'installateur : l'installateur ne fait que compiler un petit programme à partir d'un code source que vous pouvez lire, et écrit dans vos propres dossiers utilisateur. Autorisez-le, ou utilisez la voie Python.
