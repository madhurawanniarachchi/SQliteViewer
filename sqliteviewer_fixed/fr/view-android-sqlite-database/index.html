Afficher une base SQLite Android

Ouvrez une base d'application exportée depuis un émulateur, une version de débogage ou un appareil autorisé et inspectez-la sans installer d'explorateur de base de données de bureau.

Ouvrir une base Android

Exportez d'abord la base de façon légale et sûre

SQLite Viewer ouvre un fichier que vous possédez déjà ; il n'extrait pas de bases de données d'un téléphone. Utilisez le Device Explorer d'Android Studio, un émulateur, une sauvegarde d'application ou vos propres outils de débogage pour obtenir une base que vous êtes autorisé à inspecter.

Les bases d'applications Android se trouvent couramment dans un répertoire databases propre à l'application et peuvent porter l'extension .db ou aucune. Si le sélecteur du navigateur n'affiche pas une copie sans extension, renommez le fichier exporté pour qu'il se termine par .db.

Ouvrez et inspectez le schéma de l'application

  1. Déposez la base exportée sur SQLite Viewer.
  2. Recherchez dans la barre latérale des tables la fonctionnalité que vous déboguez.
  3. Ouvrez les tables probables et inspectez les lignes récentes.
  4. Utilisez le diagramme ER pour comprendre les clés étrangères et les relations de style Room.
  5. Exécutez du SQL ciblé plutôt que de faire défiler de grandes tables d'événements ou de cache.
SELECT *
FROM "sync_queue"
ORDER BY "created_at" DESC
LIMIT 0, 100;

Afficher en direct la base d'une application de débogage via USB

Dans Chrome ou Edge sur ordinateur, choisissez Android dans la barre d'outils, connectez votre téléphone avec le débogage USB activé et sélectionnez l'une de vos applications débogables. SQLite Viewer copie la base avec run-as, fusionne le journal d'écriture anticipée pour inclure les écritures récentes et peut l'actualiser toutes les quelques secondes pendant vos tests. Tout reste dans votre navigateur. Les versions de production sont protégées par Android et ne peuvent pas être lues ainsi.

Android Studio garde la connexion USB occupée ; la visionneuse propose donc aussi un mode serveur ADB : sous Windows, téléchargez l'installateur du pont en un clic et double-cliquez dessus une fois. Il met en place un petit assistant qui démarre tout seul à chaque ouverture de session, et la page partage le serveur ADB avec Android Studio pour que les deux fonctionnent en même temps. Sous macOS et Linux, lancez plutôt l'assistant adb-bridge.py. La page détecte le pont automatiquement. Aide complète : guide de configuration du pont ADB.

Vous voulez modifier des données sans redémarrer l'application ? Ajoutez un petit assistant réservé au débogage et suivez le guide de configuration de l'édition en direct.

Gérer correctement les bases WAL

SQLite peut utiliser la journalisation en écriture anticipée, ce qui produit des fichiers compagnons -wal et -shm. Copier uniquement la base principale pendant que l'application écrit peut omettre des transactions récentes. Préférez un export cohérent créé lorsque la base est fermée ou après un checkpoint.

Données sensibles : les bases d'applications peuvent contenir des informations personnelles, des jetons ou des données métier. N'utilisez que des fichiers que vous êtes autorisé à inspecter et supprimez les copies exportées une fois le débogage terminé.

Modifier des bases Android

Vous pouvez modifier une copie et la télécharger, mais remplacer la base d'une application peut enfreindre les attentes du schéma ou corrompre l'état de l'application. Conservez l'original, validez les contraintes et utilisez si possible des outils de migration ou de débogage pris en charge.
