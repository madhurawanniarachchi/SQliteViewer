Le SDL n'est pas une API complète

Un schéma de base de données décrit le stockage, tandis que GraphQL décrit un contrat tourné vers l'application. Le SDL généré ne crée ni resolvers, ni authentification, ni pagination, ni validation, ni mutations, ni autorisation au niveau des champs. Considérez-le comme un premier jet structuré.

Vérifiez la correspondance des types

Les types SQLite ne correspondent pas parfaitement aux scalaires GraphQL. Les dates peuvent être stockées en texte ou en nombres, les décimaux peuvent nécessiter un scalaire personnalisé et les données binaires demandent une représentation propre à l'application. Renommez les champs techniques de la base lorsqu'un nom d'API plus clair convient.

N'exposez jamais automatiquement toutes les tables de la base. Sélectionnez uniquement les champs et opérations auxquels les clients doivent accéder, puis appliquez l'autorisation dans la couche API.

Utilisez les relations à bon escient

Les clés étrangères déclarées peuvent suggérer des relations GraphQL, mais le comportement des resolvers dépend de l'implémentation de votre serveur. Envisagez le regroupement par lots et la pagination pour éviter des accès imbriqués coûteux à la base.
