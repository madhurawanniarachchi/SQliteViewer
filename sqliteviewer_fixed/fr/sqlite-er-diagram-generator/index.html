Générer un diagramme ER à partir de SQLite

Transformez une base de données inconnue en une carte lisible des tables, colonnes, types, clés primaires et liens de clés étrangères.

Ouvrir l'outil de diagramme ER

Créer le diagramme

  1. Ouvrez la base SQLite dans la visionneuse.
  2. Sélectionnez Diagramme ER dans la barre latérale des tables.
  3. Utilisez Ajuster pour amener toutes les entités dans la zone visible de la boîte de dialogue.
  4. Examinez les noms de colonnes, les types de données SQLite et les marqueurs de clés de chaque entité.

Les lignes de relation sont déduites des clés étrangères déclarées dans SQLite. Si une relation logique n'est pas définie par une contrainte de clé étrangère, un lecteur de schéma ne peut pas l'identifier de façon fiable à partir des seuls noms de colonnes.

Comment lire le résultat

  • PK identifie une colonne de clé primaire servant à adresser une ligne de façon unique.
  • FK identifie une colonne qui référence une clé d'une autre table.
  • Les types de colonne affichent le type SQLite déclaré. Le système de types flexible de SQLite signifie que les valeurs stockées peuvent parfois différer de cette déclaration.
  • Les liens montrent les entités référencées et référençantes.
Un diagramme est le plus utile lorsque la base déclare ses clés primaires et étrangères de manière cohérente. Des lignes manquantes indiquent souvent des contraintes manquantes plutôt qu'un problème d'affichage.

Exporter le schéma

Après avoir examiné le diagramme, exportez son schéma en SQL DDL, DBML, Mermaid ou GraphQL SDL. Le SQL DDL est le plus proche de la définition d'origine de la base. DBML et Mermaid sont utiles pour la documentation. GraphQL SDL est un point de départ pour un modèle d'API et peut nécessiter des ajustements propres à l'application.

Questions utiles pour la revue

Recherchez les tables sans clé primaire, les clés étrangères pointant vers des entités inattendues, les noms incohérents, les colonnes nullables qui devraient être obligatoires et les tables de jonction représentant des relations plusieurs-à-plusieurs. Ces vérifications aident lorsque vous héritez de la base d'une application ou préparez une migration.
