데이터베이스는 브라우저에만 있습니다

SQLite Viewer는 선택한 데이터베이스 파일의 내용을 서버에서 처리하도록 업로드하지 않고, 사용자의 기기에서 열어 처리하도록 설계되었습니다.

로컬 데이터베이스 처리

SQLite 파일을 선택하면 브라우저 JavaScript가 이를 로컬 메모리로 읽어 들입니다. 테이블 탐색, SQL 실행, 행 편집, 스키마 확인, 데이터베이스 내보내기는 브라우저 세션에서 이루어집니다. 이러한 기능을 제공하기 위해 애플리케이션이 선택한 데이터베이스 파일을 서버로 전송할 필요는 없습니다.

웹사이트가 받을 수 있는 정보

대부분의 웹사이트처럼 호스팅 인프라는 IP 주소, 브라우저 종류, 요청한 페이지, 타임스탬프, 오류 로그 같은 일반적인 요청 정보를 받을 수 있습니다. 사이트는 페이지 방문과 전반적인 사용 현황을 파악하기 위해 분석 도구를 사용할 수 있습니다. 데이터베이스 파일 이름, 테이블 내용, SQL 쿼리 텍스트는 의도적으로 분석 이벤트로 전송되어서는 안 됩니다.

브라우저 저장소

애플리케이션은 쿼리 탭이나 쿼리 기록 같은 로컬 환경설정과 작업 공간 정보를 위해 브라우저 저장소를 사용할 수 있습니다. 이 정보는 사용자 또는 브라우저가 삭제할 때까지 브라우저 프로필에 연결된 상태로 남아 있습니다.

다운로드 및 원본 파일

편집은 메모리에 있는 데이터베이스에서 이루어집니다. DB 저장은 현재 상태의 다운로드를 만듭니다. 애플리케이션은 디스크의 원본 데이터베이스 파일을 몰래 교체하지 않습니다.

사용자의 책임

접근 권한이 있는 데이터베이스만 사용하세요. 민감한 파일을 열 때는 기기, 브라우저 프로필, 설치된 확장 프로그램의 보안을 고려하세요. 공용 기기에서 작업한 뒤에는 브라우저 저장소와 다운로드한 사본을 삭제하세요.

타사 리소스

페이지는 타사 서비스에서 라이브러리, 분석 도구 또는 기타 웹사이트 리소스를 불러올 수 있습니다. 이러한 서비스는 일반적인 웹 요청 데이터를 받을 수 있지만, 선택한 데이터베이스는 그 요청에 의도적으로 포함되지 않습니다.

매우 민감하거나 규제 대상인 데이터의 경우, 조직에서 승인한 환경과 브라우저 구성을 사용하고, 사용 전에 배포된 애플리케이션의 네트워크 동작을 검토하세요.
