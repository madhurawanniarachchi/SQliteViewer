스키마 생성

  1. SQLite 데이터베이스를 엽니다.
  2. ER 다이어그램에서 엔터티를 검토합니다.
  3. 내보내기 형식으로 GraphQL SDL을 선택합니다.
  4. 타입 정의를 내보내고 API 프로젝트에서 검토합니다.
type Customer {
  id: Int!
  name: String
  orders: [Order!]
}

type Order {
  id: Int!
  customerId: Int!
}

SDL은 완전한 API가 아닙니다

데이터베이스 스키마는 저장소를 설명하고, GraphQL은 애플리케이션을 향한 계약을 설명합니다. 생성된 SDL은 리졸버, 인증, 페이지네이션, 유효성 검사, 뮤테이션, 필드 수준 권한 부여를 만들지 않습니다. 구조화된 초안으로 취급하세요.

타입 매핑 검토

SQLite 타입은 GraphQL 스칼라와 완벽하게 대응하지 않습니다. 날짜는 텍스트나 숫자로 저장될 수 있고, 소수는 사용자 정의 스칼라가 필요할 수 있으며, 바이너리 데이터는 애플리케이션별 표현이 필요합니다. 더 명확한 API 이름이 적절하다면 기술적인 데이터베이스 필드 이름을 바꾸세요.

모든 데이터베이스 테이블을 자동으로 노출하지 마세요. 클라이언트가 접근해야 하는 필드와 작업만 선택하고 API 계층에서 권한 부여를 적용하세요.

관계를 의도적으로 사용하기

선언된 외래 키는 GraphQL 관계를 암시할 수 있지만, 리졸버 동작은 서버 구현에 따라 달라집니다. 비용이 큰 중첩 데이터베이스 접근을 피하려면 일괄 처리와 페이지네이션을 고려하세요.
