ADB 브리지 설정 (Android Studio와 함께 작동)

작은 도우미 하나로 SQLite Viewer와 Android Studio가 휴대폰을 동시에 사용할 수 있습니다. 다운로드하고, 제자리에 두고, 자동으로 시작되게 하면 끝입니다.

뷰어 열기

브리지가 필요한가요?

대개 필요 없습니다. SQLite Viewer는 아무것도 설치하지 않고 USB로 휴대폰과 직접 통신할 수 있습니다(Chrome 또는 Edge의 USB 직접 모드). 브리지는 한 가지 경우를 위한 것입니다: Android Studio(또는 다른 ADB 도구)가 이미 휴대폰을 사용 중일 때입니다. USB 연결은 하나의 프로그램만 점유할 수 있으므로, 브리지를 통해 SQLite Viewer가 Android Studio의 ADB 서버를 공유합니다. 그러면 둘이 동시에 작동합니다.

Windows: 원클릭 설치 프로그램

  1. 설치 프로그램을 다운로드합니다. SQLite Viewer에서 Live Android를 열고 ADB 서버를 선택한 다음 설치 프로그램 다운로드(Windows)를 클릭하세요.
  2. 파일을 유지합니다. Chrome이 파일을 확인할 수 없다고 표시할 수 있습니다. 유지(또는 확인되지 않은 파일 다운로드)를 선택하세요. 파일은 일반 텍스트이므로 메모장으로 열어 정확히 무엇을 하는지 읽어 볼 수 있습니다.
  3. 한 번 실행합니다. Install-ADB-Bridge.cmd를 더블클릭하세요. Windows에서 Windows의 PC 보호가 표시되면 추가 정보를 클릭한 다음 실행을 클릭하세요.
  4. 페이지로 돌아옵니다. 설치 프로그램이 PC에서 브리지를 빌드하고, 로그인할 때마다 자동으로 시작되게 하고, 시작합니다. SQLite Viewer가 몇 초 안에 이를 감지합니다. 브리지로 연결을 클릭하세요.

브리지는 %LOCALAPPDATA%\SQLiteViewerBridge에 설치되며, 시작 폴더의 바로 가기가 로그인 시 이를 시작합니다. 제거하려면 해당 폴더에서 uninstall.cmd를 실행하세요.

모든 시스템: Python으로 설정

  1. Python 3을 설치합니다. python.org에서 다운로드하세요. Windows에서는 설치 프로그램에서 Add Python to PATH를 선택하세요. 대부분의 Linux 시스템에는 이미 python3가 있습니다. macOS는 기본으로 포함하지 않습니다: 처음 python3를 입력하면 macOS가 Apple의 Command Line Tools 설치를 제안합니다(수락하세요). 또는 python.org의 설치 프로그램을 사용할 수 있습니다.
  2. 파일을 다운로드합니다. adb-bridge.py를 다운로드하세요. 브라우저가 다운로드 폴더에 저장합니다. 파일 이름이 .txt로 끝나면 adb-bridge.py로 이름을 바꾸세요.
  3. 영구적인 위치로 복사합니다. 터미널을 열고(어느 폴더든 상관없으며 명령은 전체 경로를 사용합니다) 사용 중인 시스템의 명령을 실행하세요. 폴더를 만들고 파일을 복사합니다. 브라우저가 파일을 다운로드 폴더가 아닌 다른 곳에 저장했다면 명령의 해당 부분을 변경하세요.
  4. 자동으로 시작되게 합니다. 사용 중인 시스템의 명령을 실행하세요. 파일을 복사한 위치를 기준으로 로그인 시 시작 항목을 설정하고, 지금 브리지를 시작합니다.
  5. 연결합니다. SQLite Viewer로 돌아가세요. 브리지를 스스로 찾습니다. 브리지로 연결을 클릭하세요.

3단계: 파일 복사(한 번 실행)

Windows(PowerShell, Windows 키를 누르고 powershell을 입력한 뒤 Enter):

New-Item -ItemType Directory -Force "$env:LOCALAPPDATA\SQLiteViewerBridgePython" | Out-Null; Copy-Item "$env:USERPROFILE\Downloads\adb-bridge.py" "$env:LOCALAPPDATA\SQLiteViewerBridgePython\adb-bridge.py"

Windows(명령 프롬프트, Windows 키를 누르고 cmd를 입력한 뒤 Enter):

mkdir "%LOCALAPPDATA%\SQLiteViewerBridgePython" & copy "%USERPROFILE%\Downloads\adb-bridge.py" "%LOCALAPPDATA%\SQLiteViewerBridgePython\adb-bridge.py"

macOS(터미널):

mkdir -p "$HOME/Library/Application Support/SQLiteViewerBridge" && cp "$HOME/Downloads/adb-bridge.py" "$HOME/Library/Application Support/SQLiteViewerBridge/adb-bridge.py"

Linux:

mkdir -p "$HOME/.local/share/sqliteviewer-bridge" && cp "$HOME/Downloads/adb-bridge.py" "$HOME/.local/share/sqliteviewer-bridge/adb-bridge.py"

4단계: 로그인 시 자동 시작 설정(한 번 실행)

Windows(PowerShell):

python "$env:LOCALAPPDATA\SQLiteViewerBridgePython\adb-bridge.py" --add-to-startup

Windows(명령 프롬프트):

python "%LOCALAPPDATA%\SQLiteViewerBridgePython\adb-bridge.py" --add-to-startup

macOS:

python3 "$HOME/Library/Application Support/SQLiteViewerBridge/adb-bridge.py" --add-to-startup

Linux:

python3 "$HOME/.local/share/sqliteviewer-bridge/adb-bridge.py" --add-to-startup

Windows에서는 시작 폴더에 숨김 바로 가기가, macOS에서는 Launch Agent가, Linux에서는 systemd 사용자 서비스(또는 데스크톱 자동 시작 항목)가 만들어집니다. 어느 것도 관리자 권한이 필요하지 않습니다. 파일은 있는 자리에 두세요. 옮겼다면 명령을 다시 실행하세요.

급하신가요? 명령 하나로 3, 4단계 수행

파일을 다운로드한 폴더에서 터미널을 열고 실행하세요.

python adb-bridge.py --install      # Windows
python3 adb-bridge.py --install     # macOS and Linux

시작 프로그램에 직접 추가하고 싶으신가요?

Windows: Win + R을 누르고 shell:startup을 입력한 뒤 Enter를 누르세요. 열린 폴더에서 마우스 오른쪽 버튼을 클릭하고 새로 만들기 → 바로 가기를 선택한 다음 위치를 다음으로 설정하세요.

pythonw "%LOCALAPPDATA%\SQLiteViewerBridgePython\adb-bridge.py"

이름은 SQLite Viewer ADB Bridge로 하세요. python 대신 pythonw를 사용하면 검은 창이 나타나지 않습니다. 로그아웃했다가 다시 로그인하거나, 바로 가기를 더블클릭해 지금 시작하세요.

macOS: 위 명령은 ~/Library/LaunchAgents/com.sqliteviewer.adbbridge.plist를 만듭니다. Linux: ~/.config/systemd/user/sqliteviewer-bridge.service(또는 ~/.config/autostart/sqliteviewer-bridge.desktop)를 만듭니다. 이 파일들을 직접 작성할 수도 있지만 명령을 쓰는 편이 더 안전합니다.

확인, 중지 및 제거

python adb-bridge.py --status                  # is it running?
python adb-bridge.py --remove-from-startup      # stop starting at sign-in (keeps the file)
python adb-bridge.py --uninstall                # stop it and delete everything
# add the full path to the file if you are not in its folder, as in the commands above

ADB가 있나요? 없으면 설치하세요

브리지는 ADB(Android Platform Tools)로 중계합니다. Android Studio에는 이미 포함되어 있으므로 Android Studio를 사용한다면 이 섹션은 건너뛰어도 됩니다. 확인하려면 터미널을 열고 adb version을 실행하세요. 시스템이 명령을 인식하지 못하면 아래 명령 중 하나로 ADB를 설치하세요. 브리지가 실행 중이지만 ADB를 찾을 수 없는 경우에도 SQLite Viewer가 알려 줍니다. 브리지는 PATH와 Android Studio, winget, Homebrew, 수동 다운로드의 일반적인 폴더에서 ADB를 찾으므로 PATH를 바꿀 필요가 없으며, ADB 서버도 대신 시작합니다.

Windows

가장 쉬운 방법(Windows 10 및 11, PowerShell 또는 명령 프롬프트):

winget install --id Google.PlatformTools -e

winget이 없나요? 직접 다운로드하세요(PowerShell):

Invoke-WebRequest https://dl.google.com/android/repository/platform-tools-latest-windows.zip -OutFile "$env:TEMP\pt.zip"; Expand-Archive "$env:TEMP\pt.zip" "$env:LOCALAPPDATA\Android\Sdk" -Force; Remove-Item "$env:TEMP\pt.zip"

명령 프롬프트에서 같은 작업:

powershell -NoProfile -Command "Invoke-WebRequest https://dl.google.com/android/repository/platform-tools-latest-windows.zip -OutFile \"$env:TEMP\pt.zip\"; Expand-Archive \"$env:TEMP\pt.zip\" \"$env:LOCALAPPDATA\Android\Sdk\" -Force; Remove-Item \"$env:TEMP\pt.zip\""

제대로 되었는지 확인(PowerShell):

& "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe" version

macOS

Homebrew 사용:

brew install --cask android-platform-tools

Homebrew 없이:

mkdir -p "$HOME/Library/Android/sdk" && curl -L -o /tmp/pt.zip https://dl.google.com/android/repository/platform-tools-latest-darwin.zip && unzip -o /tmp/pt.zip -d "$HOME/Library/Android/sdk" && rm /tmp/pt.zip

Linux

Debian, Ubuntu, Mint:

sudo apt install adb

Fedora:

sudo dnf install android-tools

Arch, Manjaro:

sudo pacman -S android-tools

기타 배포판:

mkdir -p "$HOME/Android/Sdk" && curl -L -o /tmp/pt.zip https://dl.google.com/android/repository/platform-tools-latest-linux.zip && unzip -o /tmp/pt.zip -d "$HOME/Android/Sdk" && rm /tmp/pt.zip

그다음 휴대폰 준비

  1. 휴대폰에서 설정 → 휴대전화 정보를 열고 빌드 번호를 일곱 번 탭하세요.
  2. 설정 → 개발자 옵션을 열고 USB 디버깅을 켜세요.
  3. 휴대폰을 연결하고 표시되는 메시지에서 허용을 탭하세요. adb devices를 실행하면 device로 표시되어야 합니다.

무언가를 설정해야 하나요?

아니요. 브리지는 SQLite Viewer 웹사이트의 연결만 받아들이고, 사용자의 컴퓨터에서만 수신 대기하며(127.0.0.1), 같은 컴퓨터의 ADB 서버로만 중계합니다. 다른 곳에 저장하거나 전송하는 것은 없습니다.

설정이 필요한 경우는 두 가지뿐입니다.

  • 다른 주소에서 SQLite Viewer를 사용하는 경우(자신의 사본 또는 개발 중의 localhost). 같은 명령에서 해당 주소를 허용하세요.
python "%LOCALAPPDATA%\SQLiteViewerBridgePython\adb-bridge.py" --add-to-startup --allow-origin https://your-address.example
  • 포트 5038이 이미 사용 중인 경우. 다른 포트를 사용한 다음, Android 패널의 고급에 같은 포트를 입력하세요.
python "%LOCALAPPDATA%\SQLiteViewerBridgePython\adb-bridge.py" --add-to-startup --port 5040

허용된 주소는 브리지 옆의 origins.txt 파일(한 줄에 주소 하나)에 기억됩니다. Windows는 %LOCALAPPDATA%\SQLiteViewerBridge(설치 프로그램) 또는 %LOCALAPPDATA%\SQLiteViewerBridgePython(Python), macOS는 ~/Library/Application Support/SQLiteViewerBridge, Linux는 ~/.local/share/sqliteviewer-bridge입니다.

문제 해결

  • “The bridge is not running on this computer”: 설치 프로그램이나 위의 명령을 실행하거나, 로그아웃했다가 다시 로그인하세요. 그런 다음 Android 패널을 다시 여세요.
  • Python이 없습니다: Windows에서는 필요하지 않으니 위의 원클릭 설치 프로그램을 사용하세요. 그 외에는 python.org에서 Python 3을 설치하거나(Windows: Add Python to PATH 선택), macOS에서는 Command Line Tools 설치 제안을 수락하세요. 그런 다음 명령을 다시 실행하세요.
  • python이 인식되지 않거나 Microsoft Store가 열림(Windows): Python이 아직 설치되지 않았거나 PATH 옵션을 놓쳤습니다. python.org에서 설치하거나 명령의 python을 py로 바꾸세요. 설정 → 앱 → 고급 앱 설정 → 앱 실행 별칭에서 Store 바로 가기를 끌 수도 있습니다.
  • 복사 명령이 파일을 찾을 수 없다고 함: 브라우저가 adb-bridge.py를 다운로드 폴더가 아닌 다른 곳에 저장했습니다. 명령의 해당 부분을 변경하거나 .txt 파일의 이름을 바꾸세요.
  • “Something is already listening on port 5038”: 다른 브리지가 실행 중입니다. 이전 것을 제거하거나(--uninstall 또는 uninstall.cmd) --port로 다른 포트를 선택하세요.
  • 브리지는 실행되지만 휴대폰이 나타나지 않음: ADB 서버가 휴대폰을 인식해야 합니다. adb devices를 실행하고, USB 디버깅을 켜고, 휴대폰의 “USB 디버깅을 허용하시겠습니까?” 메시지를 수락하세요.
  • “The bridge is running, but ADB is not installed”: 위의 ADB가 있나요? 섹션의 명령으로 ADB를 설치하세요(또는 Android Studio를 설치). 몇 초 뒤 페이지가 스스로 감지합니다.
  • Chrome이 네트워크의 기기에 대한 접근 허용을 요청함: 허용하세요. 페이지가 사용자의 컴퓨터에 있는 브리지에 도달하는 방식입니다.
  • 바이러스 백신이나 Windows가 설치 프로그램을 차단함: 설치 프로그램은 읽을 수 있는 소스에서 작은 프로그램을 빌드하고 사용자 폴더에만 기록합니다. 허용하거나 대신 Python 방식을 사용하세요.
