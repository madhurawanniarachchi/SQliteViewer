SQLite에서 ER 다이어그램 생성

낯선 데이터베이스를 테이블, 열, 형식, 기본 키, 외래 키 연결이 보이는 읽기 쉬운 지도로 바꿔 보세요.

ER 다이어그램 도구 열기

다이어그램 만들기

  1. 뷰어에서 SQLite 데이터베이스를 엽니다.
  2. 테이블 사이드바에서 ER 다이어그램을 선택합니다.
  3. 맞춤을 사용하면 모든 엔터티가 대화상자 화면에 들어옵니다.
  4. 각 엔터티의 열 이름, SQLite 데이터 형식, 키 표시를 확인합니다.

관계선은 SQLite에 선언된 외래 키에서 만들어집니다. 논리적 관계가 외래 키 제약 조건으로 정의되어 있지 않으면, 스키마 리더는 열 이름만으로는 이를 안정적으로 알아낼 수 없습니다.

결과를 읽는 방법

  • PK는 행을 고유하게 지정하는 데 쓰이는 기본 키 열을 나타냅니다.
  • FK는 다른 테이블의 키를 참조하는 열을 나타냅니다.
  • 열 형식은 선언된 SQLite 형식을 보여 줍니다. SQLite의 형식 시스템은 유연하므로 저장된 값이 선언과 다를 수도 있습니다.
  • 연결선은 참조되는 엔터티와 참조하는 엔터티를 보여 줍니다.
데이터베이스가 기본 키와 외래 키를 일관되게 선언했을 때 다이어그램이 가장 유용합니다. 선이 없다면 렌더링 문제가 아니라 제약 조건이 빠져 있는 경우가 많습니다.

스키마 내보내기

다이어그램을 검토한 뒤 스키마를 SQL DDL, DBML, Mermaid 또는 GraphQL SDL로 내보내세요. SQL DDL은 원래 데이터베이스 정의와 가장 가깝습니다. DBML과 Mermaid는 문서화에 유용합니다. GraphQL SDL은 API 모델의 출발점이며 애플리케이션에 맞는 조정이 필요할 수 있습니다.

검토에 유용한 질문

기본 키가 없는 테이블, 예상치 못한 엔터티를 가리키는 외래 키, 일관되지 않은 이름, 필수여야 하는데 NULL을 허용하는 열, 다대다 관계를 나타내는 연결 테이블을 찾아보세요. 애플리케이션 데이터베이스를 인수하거나 마이그레이션을 계획할 때 이런 점검이 도움이 됩니다.
