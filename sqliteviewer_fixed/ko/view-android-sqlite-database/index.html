Android 데이터베이스 열기

먼저 합법적이고 안전하게 데이터베이스를 내보내세요

SQLite Viewer는 이미 가지고 있는 파일을 엽니다. 휴대폰에서 데이터베이스를 추출하지는 않습니다. 확인할 권한이 있는 데이터베이스를 얻으려면 Android Studio의 Device Explorer, 에뮬레이터, 앱 백업 또는 자체 디버그 도구를 사용하세요.

Android 앱 데이터베이스는 보통 앱 고유의 databases 디렉터리에 있으며 .db 확장자를 쓰거나 확장자가 없을 수 있습니다. 브라우저 파일 선택기에 확장자 없는 사본이 보이지 않으면, 내보낸 파일 이름이 .db로 끝나도록 바꾸세요.

앱 스키마 열기 및 확인

  1. 내보낸 데이터베이스를 SQLite Viewer에 놓습니다.
  2. 테이블 사이드바에서 디버깅 중인 기능을 검색합니다.
  3. 관련 있어 보이는 테이블을 열고 최근 행을 확인합니다.
  4. ER 다이어그램으로 외래 키와 Room 스타일의 관계를 이해합니다.
  5. 큰 이벤트 또는 캐시 테이블을 스크롤하는 대신 목적이 분명한 SQL을 실행합니다.
SELECT *
FROM "sync_queue"
ORDER BY "created_at" DESC
LIMIT 0, 100;

USB로 디버그 앱 데이터베이스를 실시간으로 보기

데스크톱의 Chrome 또는 Edge에서 도구 모음의 Android를 선택하고, USB 디버깅을 켠 휴대폰을 연결한 다음 디버그 가능한 앱 중 하나를 고르세요. SQLite Viewer는 run-as로 데이터베이스를 복사하고, 최근 쓰기가 포함되도록 선행 기록 로그를 병합하며, 테스트하는 동안 몇 초마다 새로 고칠 수 있습니다. 모든 것이 브라우저 안에 머무릅니다. 릴리스 빌드는 Android가 보호하므로 이 방식으로 읽을 수 없습니다.

Android Studio가 USB 연결을 점유하므로, 뷰어에는 ADB 서버 모드도 있습니다. Windows에서는 원클릭 브리지 설치 프로그램을 다운로드해 한 번 더블클릭하세요. 로그인할 때마다 자동으로 시작되는 작은 도우미가 설정되며, 페이지가 Android Studio와 ADB 서버를 공유하므로 둘을 동시에 사용할 수 있습니다. macOS와 Linux에서는 대신 adb-bridge.py 도우미를 실행하세요. 페이지가 브리지를 자동으로 감지합니다. 전체 도움말: ADB 브리지 설정 가이드.

앱을 다시 시작하지 않고 데이터를 변경하고 싶으신가요? 디버그 전용 작은 도우미를 추가하고 실시간 편집 설정 가이드를 따르세요.

WAL 데이터베이스를 올바르게 다루기

SQLite는 선행 기록 로깅을 사용할 수 있으며, 이때 -wal 및 -shm 보조 파일이 생성됩니다. 앱이 쓰는 도중 메인 데이터베이스만 복사하면 최근 트랜잭션이 빠질 수 있습니다. 데이터베이스를 닫은 상태나 체크포인트 후에 만든 일관된 내보내기를 사용하세요.

민감한 데이터: 앱 데이터베이스에는 개인정보, 토큰 또는 비즈니스 기록이 들어 있을 수 있습니다. 확인할 권한이 있는 파일만 사용하고, 디버깅이 끝나면 내보낸 사본을 삭제하세요.

Android 데이터베이스 편집

사본을 편집해 다운로드할 수 있지만, 앱 데이터베이스를 교체하면 스키마 기대치를 위반하거나 애플리케이션 상태가 손상될 수 있습니다. 원본을 보관하고, 제약 조건을 검증하며, 가능하면 지원되는 마이그레이션 또는 디버그 도구를 사용하세요.
