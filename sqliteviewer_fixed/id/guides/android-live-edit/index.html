Debugging langsung Android

Edit database aplikasi Android secara langsung tanpa memulai ulang aplikasi

Tambahkan pembantu kecil khusus debug ke aplikasi Anda dan edit database SQLite-nya dari browser selagi aplikasi tetap berjalan.

Buka penampil

Apa yang Anda dapatkan

Live edit bekerja seperti Database Inspector Android Studio, tetapi dari browser Anda. SQLite Viewer mengirim setiap perubahan ke ContentProvider kecil di dalam aplikasi debug Anda, yang menjalankannya pada database aplikasi itu sendiri. Aplikasi tetap berjalan, dan tidak ada yang perlu dihentikan, disalin, atau dimulai ulang.

Hanya build debug. Pembantu ini memungkinkan siapa pun dengan akses debugging USB menjalankan pernyataan tulis pada database, jadi daftarkan hanya di src/debug dan jangan pernah menyertakannya di build rilis.

Cara menyiapkannya

  1. Tambahkan kelas pembantu. Unduh SqliteViewerProvider.kt (atau salin kode di bawah) ke modul aplikasi Anda, misalnya app/src/main/java/com/example/debughelper/. Ubah baris package agar sesuai dengan folder.
  2. Daftarkan hanya untuk build debug. Buat app/src/debug/AndroidManifest.xml dengan entri provider di bawah. Karena berada di source set debug, build rilis tidak pernah memuat entri tersebut dan tidak ada yang terekspos.
  3. Opsional: segarkan layar Room. Room hanya menyadari perubahan yang dibuat melalui koneksinya sendiri. Atur hook afterWrite sekali agar layar LiveData dan Flow Anda diperbarui tepat setelah live edit.
  4. Jalankan build debug. Pasang build debug Anda di ponsel dan buka aplikasi sekali agar Android mendaftarkan provider.
  5. Aktifkan Live edit. Di SQLite Viewer pilih Android, hubungkan ponsel, buka database aplikasi, dan centang Live edit. Lencana hijau LIVE EDIT muncul. Sekarang setiap edit baris, penyisipan, penghapusan, dan pernyataan SQL yang Anda jalankan juga diterapkan ke aplikasi yang sedang berjalan.

Manifes debug

<?xml version="1.0" encoding="utf-8"?>
<!-- src/debug/AndroidManifest.xml  (debug builds only) -->
<manifest xmlns:android="http://schemas.android.com/apk/res/android">
    <application>
        <provider
            android:name="com.example.debughelper.SqliteViewerProvider"
            android:authorities="${applicationId}.sqliteviewer"
            android:exported="true" />
    </application>
</manifest>

Hook Room opsional

// In your Application class (optional, only if you use Room LiveData / Flow)
override fun onCreate() {
    super.onCreate()
    if (BuildConfig.DEBUG) {
        SqliteViewerProvider.afterWrite = {
            AppDatabase.getInstance(this).invalidationTracker.refreshVersionsAsync()
        }
    }
}

Pembantu (SqliteViewerProvider.kt)

package com.example.debughelper // use any package, for example your app's own

import android.content.ContentProvider
import android.content.ContentValues
import android.database.Cursor
import android.database.sqlite.SQLiteDatabase
import android.net.Uri
import android.os.Bundle
import android.util.Base64
import org.json.JSONArray

/**
 * DEBUG BUILDS ONLY.
 *
 * Lets SQLite Viewer (https://sqliteviewer.codemasterlk.com) edit this app's databases
 * while the app keeps running. The class can live in src/main, but it is only registered
 * in src/debug/AndroidManifest.xml, so release builds never expose it.
 */
class SqliteViewerProvider : ContentProvider() {

    companion object {
        /** Optional: called after every successful live edit, e.g. to refresh Room observers. */
        @JvmStatic
        var afterWrite: (() -> Unit)? = null

        private val allowedStatement = Regex("""^(INSERT|UPDATE|DELETE|REPLACE|CREATE|DROP|ALTER)\b""", RegexOption.IGNORE_CASE)
        private val leadingNoise = Regex("""^(\s|--[^\n]*\n|/\*.*?\*/)*""", RegexOption.DOT_MATCHES_ALL)
        private val safeName = Regex("""^[A-Za-z0-9._-]+$""")
    }

    private val handles = HashMap<String, SQLiteDatabase>()

    override fun onCreate(): Boolean = true

    override fun call(method: String, arg: String?, extras: Bundle?): Bundle {
        val answer = try {
            when (method) {
                "ping" -> "OK:1"
                "batch" -> "OK:" + runBatch(extras?.getString("db"), arg)
                else -> "ERR:unknown method $method"
            }
        } catch (e: Throwable) {
            "ERR:" + (e.message ?: e.javaClass.simpleName).replace('\n', ' ')
        }
        return Bundle().apply { putString("r", answer) }
    }

    @Synchronized
    private fun database(name: String): SQLiteDatabase {
        handles[name]?.let { if (it.isOpen) return it }

        val file = context!!.getDatabasePath(name)
        require(file.exists()) { "database not found: $name" }

        return SQLiteDatabase.openDatabase(file.path, null, SQLiteDatabase.OPEN_READWRITE)
            .also { handles[name] = it }
    }

    private fun runBatch(name: String?, base64: String?): Int {
        require(name != null && safeName.matches(name)) { "invalid database name" }
        require(!base64.isNullOrEmpty()) { "no statements" }

        val statements = JSONArray(String(Base64.decode(base64, Base64.DEFAULT), Charsets.UTF_8))
        val db = database(name)

        db.beginTransaction()
        try {
            for (i in 0 until statements.length()) {
                val sql = statements.getString(i)
                require(allowedStatement.containsMatchIn(sql.replaceFirst(leadingNoise, ""))) {
                    "statement type not allowed"
                }
                db.execSQL(sql)
            }
            db.setTransactionSuccessful()
        } finally {
            db.endTransaction()
        }

        afterWrite?.invoke()
        return statements.length()
    }

    // Not used: the viewer talks to this provider only through call().
    override fun query(uri: Uri, projection: Array<String>?, selection: String?, selectionArgs: Array<String>?, sortOrder: String?): Cursor? = null
    override fun getType(uri: Uri): String? = null
    override fun insert(uri: Uri, values: ContentValues?): Uri? = null
    override fun delete(uri: Uri, selection: String?, selectionArgs: Array<String>?): Int = 0
    override fun update(uri: Uri, values: ContentValues?, selection: String?, selectionArgs: Array<String>?): Int = 0
}

Apa yang bisa dan tidak bisa dilakukannya

  • Ia menjalankan pernyataan INSERT, UPDATE, DELETE, REPLACE, CREATE, DROP, dan ALTER. Pembacaan, PRAGMA, dan VACUUM ditolak.
  • Setiap edit diterapkan dalam transaksi. Jika aplikasi menolaknya, SQLite Viewer menampilkan kesalahan dan memuat ulang data dari ponsel agar keduanya tetap sinkron.
  • Edit yang sangat besar (sekitar 75 KB SQL) tidak dikirim secara langsung. Gunakan Kirim ke ponsel untuk itu. Cara ini mengganti seluruh file database dan memulai ulang aplikasi.
  • Nama database harus cocok dengan file di folder databases aplikasi. Pembantu menggunakan nama paket aplikasi debug, sehingga juga berfungsi dengan applicationIdSuffix.
  • Berfungsi dengan Android Studio yang berjalan bersamaan saat Anda menggunakan mode server ADB pada panel Android (panduan penyiapan bridge).

Pemecahan masalah

  • “Live-edit helper not found”: entri manifes debug tidak ada, aplikasi belum dipasang ulang, atau nama paket berbeda. Authority provider harus <paket Anda>.sqliteviewer.
  • “database not found”: buka aplikasi sekali agar membuat databasenya, lalu coba lagi.
  • Layar tidak diperbarui: tambahkan hook Room opsional di atas, atau buka ulang layar.
