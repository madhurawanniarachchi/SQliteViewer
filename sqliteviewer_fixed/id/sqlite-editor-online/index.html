Edit baris dengan perlindungan primary key

Buka database dan pilih tabel. Jika tabel memiliki primary key yang dapat digunakan, hasilnya menyertakan aksi untuk mengedit dan menghapus baris satu per satu. Editor menggunakan nilai primary key untuk menargetkan baris yang dimaksud, bukan bergantung pada posisi visualnya.

  1. Pilih Edit pada baris.
  2. Ubah nilai kolom yang diperlukan. Gunakan opsi null bila kolom mengizinkannya.
  3. Simpan baris dan pastikan hasilnya sudah diperbarui.
  4. Pilih Simpan DB untuk mengunduh database setelah selesai.
Penting: perubahan dilakukan pada database yang ada di memori browser. Perubahan tidak menimpa file asli secara otomatis. Unduh database terbaru sebelum menutup halaman.

Gunakan SQL untuk perubahan massal

Ruang kerja kueri juga mendukung pernyataan tulis SQLite. Contohnya:

UPDATE "products"
SET "active" = 0
WHERE "last_order_at" < '2025-01-01';

Periksa kondisi WHERE dengan cermat sebelum menjalankan update atau delete. Alur kerja yang baik adalah menjalankan kondisi yang sama sebagai SELECT terlebih dahulu, memastikan baris yang terdampak, lalu baru menjalankan kueri tulis.

Apa yang dapat menghalangi pengeditan baris?

Aksi baris yang aman mengharuskan penampil mengenali rekaman secara andal. Tabel tanpa primary key mungkin ditampilkan hanya-baca pada antarmuka baris. View, hasil terhitung, join, dan kueri agregat umumnya tidak dapat dipetakan dengan aman ke satu baris sumber, meskipun Anda tetap dapat memeriksa atau mengekspornya.

Unduh database yang sudah selesai

Aksi Simpan DB mengekspor status database SQLite saat ini, termasuk edit baris dan kueri tulis yang berhasil. Simpan file asli sebagai cadangan sampai Anda menguji file yang diunduh di aplikasi yang menggunakannya.
