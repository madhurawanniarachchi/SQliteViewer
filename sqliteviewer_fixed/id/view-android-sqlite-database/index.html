Ekspor database dulu secara legal dan aman

SQLite Viewer membuka file yang sudah Anda miliki; ia tidak mengekstrak database dari ponsel. Gunakan Device Explorer Android Studio, emulator, cadangan aplikasi, atau alat debug Anda sendiri untuk mendapatkan database yang berwenang Anda periksa.

Database aplikasi Android biasanya berada di direktori databases khusus aplikasi dan dapat menggunakan .db atau tanpa ekstensi. Jika pemilih file browser tidak menampilkan salinan tanpa ekstensi, ganti nama file hasil ekspor agar berakhiran .db.

Buka dan periksa skema aplikasi

  1. Letakkan database hasil ekspor ke SQLite Viewer.
  2. Cari fitur yang sedang Anda debug di sidebar tabel.
  3. Buka tabel yang mungkin relevan dan periksa baris terbaru.
  4. Gunakan diagram ER untuk memahami foreign key dan relasi ala Room.
  5. Jalankan SQL yang terfokus alih-alih menggulir tabel event atau cache yang besar.
SELECT *
FROM "sync_queue"
ORDER BY "created_at" DESC
LIMIT 0, 100;

Lihat database aplikasi debug secara langsung lewat USB

Di Chrome atau Edge desktop, pilih Android di toolbar, hubungkan ponsel dengan USB debugging aktif, dan pilih salah satu aplikasi Anda yang dapat di-debug. SQLite Viewer menyalin database dengan run-as, menggabungkan write-ahead log agar tulisan terbaru ikut tersertakan, dan dapat menyegarkannya setiap beberapa detik saat Anda menguji. Semuanya tetap berada di browser Anda. Build rilis dilindungi oleh Android dan tidak dapat dibaca dengan cara ini.

Android Studio membuat koneksi USB sibuk, sehingga penampil juga memiliki mode server ADB: di Windows, unduh penginstal bridge sekali klik dan klik dua kali sekali saja. Ini menyiapkan pembantu kecil yang berjalan sendiri setiap kali Anda masuk, dan halaman berbagi server ADB dengan Android Studio sehingga keduanya dapat bekerja bersamaan. Di macOS dan Linux, jalankan pembantu adb-bridge.py. Halaman mendeteksi bridge secara otomatis. Bantuan lengkap: panduan penyiapan bridge ADB.

Ingin mengubah data tanpa memulai ulang aplikasi? Tambahkan pembantu kecil khusus debug dan ikuti panduan penyiapan live edit.

Tangani database WAL dengan benar

SQLite dapat menggunakan write-ahead logging, yang menghasilkan file pendamping -wal dan -shm. Menyalin hanya database utama saat aplikasi sedang menulis dapat melewatkan transaksi terbaru. Pilih ekspor yang konsisten yang dibuat saat database ditutup atau di-checkpoint.

Data sensitif: database aplikasi dapat berisi informasi pribadi, token, atau catatan bisnis. Gunakan hanya file yang berwenang Anda periksa dan hapus salinan hasil ekspor setelah debugging selesai.

Mengedit database Android

Anda dapat mengedit salinan dan mengunduhnya, tetapi mengganti database aplikasi dapat melanggar ekspektasi skema atau merusak status aplikasi. Simpan yang asli, validasi constraint, dan gunakan alat migrasi atau debug yang didukung bila memungkinkan.
