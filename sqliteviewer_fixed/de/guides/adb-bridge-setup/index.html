Android-Live-Debugging

Die ADB-Bridge einrichten (funktioniert parallel zu Android Studio)

Ein kleiner Helfer lässt SQLite Viewer und Android Studio Ihr Telefon gleichzeitig nutzen. Laden Sie ihn herunter, legen Sie ihn ab, lassen Sie ihn selbst starten – fertig.

Viewer öffnen

Brauche ich die Bridge?

Oft nicht. SQLite Viewer kann direkt per USB mit Ihrem Telefon kommunizieren (Modus USB direkt in Chrome oder Edge), ohne dass etwas installiert werden muss. Die Bridge ist für genau einen Fall gedacht: Android Studio (oder ein anderes ADB-Werkzeug) nutzt das Telefon bereits. Nur ein Programm kann die USB-Verbindung belegen, daher lässt die Bridge SQLite Viewer den ADB-Server von Android Studio mitbenutzen. Beide funktionieren dann gleichzeitig.

Windows: Ein-Klick-Installer

  1. Laden Sie den Installer herunter. Öffnen Sie in SQLite Viewer Live Android, wählen Sie ADB-Server und klicken Sie auf Installer herunterladen (Windows).
  2. Behalten Sie die Datei. Chrome meldet eventuell, dass die Datei nicht überprüft werden kann. Wählen Sie Behalten (oder Nicht überprüfte Datei herunterladen). Die Datei ist reiner Text, Sie können sie also im Editor öffnen und genau nachlesen, was sie tut.
  3. Führen Sie sie einmal aus. Doppelklicken Sie auf Install-ADB-Bridge.cmd. Zeigt Windows Der Computer wurde durch Windows geschützt, klicken Sie auf Weitere Informationen und dann auf Trotzdem ausführen.
  4. Kehren Sie zur Seite zurück. Der Installer baut die Bridge auf Ihrem PC, lässt sie bei jeder Anmeldung selbst starten und startet sie. SQLite Viewer bemerkt sie nach wenigen Sekunden. Klicken Sie auf Über Bridge verbinden.

Die Bridge wird in %LOCALAPPDATA%\SQLiteViewerBridge installiert, und eine Verknüpfung im Autostart-Ordner startet sie bei der Anmeldung. Zum Entfernen führen Sie uninstall.cmd aus diesem Ordner aus.

Jedes System: Einrichtung mit Python

  1. Python 3 installieren. Laden Sie es von python.org herunter. Aktivieren Sie unter Windows im Installer Add Python to PATH. Die meisten Linux-Systeme haben python3 bereits. macOS enthält es standardmäßig nicht: Wenn Sie zum ersten Mal python3 eingeben, bietet macOS an, Apples Command Line Tools zu installieren (akzeptieren Sie), oder Sie nutzen den Installer von python.org.
  2. Datei herunterladen. Laden Sie adb-bridge.py herunter. Ihr Browser speichert sie im Ordner „Downloads“. Endet sie auf .txt, benennen Sie sie in adb-bridge.py um.
  3. An den endgültigen Ort kopieren. Öffnen Sie ein Terminal (jeder Ordner genügt, die Befehle verwenden vollständige Pfade) und führen Sie den Befehl für Ihr System aus. Er legt den Ordner an und kopiert die Datei hinein. Hat Ihr Browser die Datei woanders als in „Downloads“ gespeichert, ändern Sie diesen Teil des Befehls.
  4. Selbststart einrichten. Führen Sie den Befehl für Ihr System aus. Er richtet den Autostart-Eintrag für die Datei an dem Ort ein, wohin Sie sie kopiert haben, und startet die Bridge jetzt.
  5. Verbinden. Wechseln Sie zurück zu SQLite Viewer. Er findet die Bridge selbst. Klicken Sie auf Über Bridge verbinden.

Schritt 3: Datei kopieren (einmal ausführen)

Windows (PowerShell; Windows-Taste drücken, powershell eingeben, Enter drücken):

New-Item -ItemType Directory -Force "$env:LOCALAPPDATA\SQLiteViewerBridgePython" | Out-Null; Copy-Item "$env:USERPROFILE\Downloads\adb-bridge.py" "$env:LOCALAPPDATA\SQLiteViewerBridgePython\adb-bridge.py"

Windows (Eingabeaufforderung; Windows-Taste drücken, cmd eingeben, Enter drücken):

mkdir "%LOCALAPPDATA%\SQLiteViewerBridgePython" & copy "%USERPROFILE%\Downloads\adb-bridge.py" "%LOCALAPPDATA%\SQLiteViewerBridgePython\adb-bridge.py"

macOS (Terminal):

mkdir -p "$HOME/Library/Application Support/SQLiteViewerBridge" && cp "$HOME/Downloads/adb-bridge.py" "$HOME/Library/Application Support/SQLiteViewerBridge/adb-bridge.py"

Linux:

mkdir -p "$HOME/.local/share/sqliteviewer-bridge" && cp "$HOME/Downloads/adb-bridge.py" "$HOME/.local/share/sqliteviewer-bridge/adb-bridge.py"

Schritt 4: Selbststart bei der Anmeldung einrichten (einmal ausführen)

Windows (PowerShell):

python "$env:LOCALAPPDATA\SQLiteViewerBridgePython\adb-bridge.py" --add-to-startup

Windows (Eingabeaufforderung):

python "%LOCALAPPDATA%\SQLiteViewerBridgePython\adb-bridge.py" --add-to-startup

macOS:

python3 "$HOME/Library/Application Support/SQLiteViewerBridge/adb-bridge.py" --add-to-startup

Linux:

python3 "$HOME/.local/share/sqliteviewer-bridge/adb-bridge.py" --add-to-startup

Unter Windows erzeugt dies eine ausgeblendete Verknüpfung im Autostart-Ordner, unter macOS einen Launch Agent und unter Linux einen systemd-Benutzerdienst (oder einen Desktop-Autostart-Eintrag). Keiner davon benötigt Administratorrechte. Lassen Sie die Datei, wo sie ist; wenn Sie sie verschieben, führen Sie den Befehl erneut aus.

In Eile? Ein Befehl erledigt Schritt 3 und 4

Öffnen Sie ein Terminal in dem Ordner, in den Sie die Datei heruntergeladen haben, und führen Sie aus:

python adb-bridge.py --install      # Windows
python3 adb-bridge.py --install     # macOS and Linux

Lieber von Hand in den Autostart legen?

Windows: Drücken Sie Win + R, geben Sie shell:startup ein und drücken Sie Enter. Klicken Sie im geöffneten Ordner mit der rechten Maustaste, wählen Sie Neu → Verknüpfung und setzen Sie den Speicherort auf:

pythonw "%LOCALAPPDATA%\SQLiteViewerBridgePython\adb-bridge.py"

Nennen Sie sie SQLite Viewer ADB Bridge. Mit pythonw statt python erscheint kein schwarzes Fenster. Melden Sie sich ab und wieder an oder doppelklicken Sie auf die Verknüpfung, um sie jetzt zu starten.

macOS: Der obige Befehl erstellt ~/Library/LaunchAgents/com.sqliteviewer.adbbridge.plist. Linux: Er erstellt ~/.config/systemd/user/sqliteviewer-bridge.service (oder ~/.config/autostart/sqliteviewer-bridge.desktop). Diese Dateien lassen sich auch von Hand schreiben, der Befehl ist aber sicherer.

Prüfen, beenden und entfernen

python adb-bridge.py --status                  # is it running?
python adb-bridge.py --remove-from-startup      # stop starting at sign-in (keeps the file)
python adb-bridge.py --uninstall                # stop it and delete everything
# add the full path to the file if you are not in its folder, as in the commands above

Habe ich ADB? Falls nicht, installieren

Die Bridge leitet an ADB (Android Platform Tools) weiter. Android Studio enthält es bereits; wenn Sie Android Studio nutzen, können Sie diesen Abschnitt überspringen. Zum Prüfen öffnen Sie ein Terminal und führen adb version aus. Kennt das System den Befehl nicht, installieren Sie ADB mit einem der Befehle unten. SQLite Viewer meldet auch, wenn die Bridge läuft, aber ADB nicht findet. Die Bridge sucht ADB in Ihrem PATH und in den üblichen Ordnern von Android Studio, winget, Homebrew und manuellen Downloads, Sie müssen den PATH also nicht ändern, und sie startet den ADB-Server für Sie.

Windows

Am einfachsten (Windows 10 und 11, PowerShell oder Eingabeaufforderung):

winget install --id Google.PlatformTools -e

Kein winget? Direkt herunterladen (PowerShell):

Invoke-WebRequest https://dl.google.com/android/repository/platform-tools-latest-windows.zip -OutFile "$env:TEMP\pt.zip"; Expand-Archive "$env:TEMP\pt.zip" "$env:LOCALAPPDATA\Android\Sdk" -Force; Remove-Item "$env:TEMP\pt.zip"

Dasselbe in der Eingabeaufforderung:

powershell -NoProfile -Command "Invoke-WebRequest https://dl.google.com/android/repository/platform-tools-latest-windows.zip -OutFile \"$env:TEMP\pt.zip\"; Expand-Archive \"$env:TEMP\pt.zip\" \"$env:LOCALAPPDATA\Android\Sdk\" -Force; Remove-Item \"$env:TEMP\pt.zip\""

Prüfen, ob es funktioniert hat (PowerShell):

& "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe" version

macOS

Mit Homebrew:

brew install --cask android-platform-tools

Ohne Homebrew:

mkdir -p "$HOME/Library/Android/sdk" && curl -L -o /tmp/pt.zip https://dl.google.com/android/repository/platform-tools-latest-darwin.zip && unzip -o /tmp/pt.zip -d "$HOME/Library/Android/sdk" && rm /tmp/pt.zip

Linux

Debian, Ubuntu, Mint:

sudo apt install adb

Fedora:

sudo dnf install android-tools

Arch, Manjaro:

sudo pacman -S android-tools

Jede andere Distribution:

mkdir -p "$HOME/Android/Sdk" && curl -L -o /tmp/pt.zip https://dl.google.com/android/repository/platform-tools-latest-linux.zip && unzip -o /tmp/pt.zip -d "$HOME/Android/Sdk" && rm /tmp/pt.zip

Danach das Telefon vorbereiten

  1. Öffnen Sie auf dem Telefon Einstellungen → Über das Telefon und tippen Sie siebenmal auf Build-Nummer.
  2. Öffnen Sie Einstellungen → Entwickleroptionen und aktivieren Sie das USB-Debugging.
  3. Schließen Sie das Telefon an und tippen Sie in der Abfrage auf Zulassen. adb devices sollte es als device auflisten.

Muss ich etwas konfigurieren?

Nein. Die Bridge akzeptiert nur Verbindungen von der SQLite-Viewer-Website, lauscht nur auf Ihrem eigenen Computer (127.0.0.1) und leitet nur an den ADB-Server auf demselben Computer weiter. Nichts wird gespeichert oder anderswohin gesendet.

Nur in zwei Fällen brauchen Sie eine Einstellung:

  • Sie nutzen SQLite Viewer von einer anderen Adresse (Ihre eigene Kopie oder localhost während der Entwicklung). Erlauben Sie diese Adresse in denselben Befehlen:
python "%LOCALAPPDATA%\SQLiteViewerBridgePython\adb-bridge.py" --add-to-startup --allow-origin https://your-address.example
  • Port 5038 ist bereits belegt. Verwenden Sie einen anderen Port und geben Sie denselben Port unter Erweitert im Android-Bereich ein:
python "%LOCALAPPDATA%\SQLiteViewerBridgePython\adb-bridge.py" --add-to-startup --port 5040

Erlaubte Adressen werden in einer Datei namens origins.txt (eine Adresse pro Zeile) neben der Bridge gespeichert: unter Windows %LOCALAPPDATA%\SQLiteViewerBridge (Installer) oder %LOCALAPPDATA%\SQLiteViewerBridgePython (Python), unter macOS ~/Library/Application Support/SQLiteViewerBridge, unter Linux ~/.local/share/sqliteviewer-bridge.

Fehlerbehebung

  • „The bridge is not running on this computer“: Führen Sie den Installer oder die obigen Befehle aus oder melden Sie sich ab und wieder an. Öffnen Sie dann den Android-Bereich erneut.
  • Ich habe kein Python: Unter Windows brauchen Sie es nicht, nutzen Sie den Ein-Klick-Installer oben. Andernfalls installieren Sie Python 3 von python.org (Windows: Add Python to PATH aktivieren) oder akzeptieren unter macOS das Angebot, die Command Line Tools zu installieren. Führen Sie die Befehle dann erneut aus.
  • python wird nicht erkannt oder öffnet den Microsoft Store (Windows): Python ist noch nicht installiert oder die PATH-Option wurde übersehen. Installieren Sie es von python.org oder ersetzen Sie in den Befehlen python durch py. Sie können die Store-Verknüpfung auch unter Einstellungen → Apps → Erweiterte App-Einstellungen → App-Ausführungsaliase ausschalten.
  • Der Kopierbefehl meldet, die Datei werde nicht gefunden: Ihr Browser hat adb-bridge.py woanders als in „Downloads“ gespeichert. Ändern Sie diesen Teil des Befehls oder benennen Sie eine .txt-Datei um.
  • „Something is already listening on port 5038“: Eine andere Bridge läuft. Entfernen Sie die alte (--uninstall oder uninstall.cmd) oder wählen Sie mit --port einen anderen Port.
  • Die Bridge läuft, aber kein Telefon erscheint: Der ADB-Server muss das Telefon sehen. Führen Sie adb devices aus, aktivieren Sie das USB-Debugging und bestätigen Sie am Telefon die Abfrage „USB-Debugging zulassen“.
  • „The bridge is running, but ADB is not installed“: Installieren Sie ADB mit den Befehlen im Abschnitt Habe ich ADB? oben (oder installieren Sie Android Studio). Die Seite bemerkt es einige Sekunden später von selbst.
  • Chrome fragt, ob der Zugriff auf Geräte in Ihrem Netzwerk erlaubt werden soll: Erlauben Sie es. So erreicht die Seite die Bridge auf Ihrem eigenen Computer.
  • Virenschutz oder Windows blockiert den Installer: Der Installer baut nur ein kleines Programm aus lesbarem Quellcode und schreibt in Ihre eigenen Benutzerordner. Erlauben Sie ihn oder nutzen Sie stattdessen den Python-Weg.
