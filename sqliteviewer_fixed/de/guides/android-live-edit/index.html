Android-Live-Debugging

Datenbank einer Android-App bearbeiten, ohne die App neu zu starten

Fügen Sie Ihrer App einen kleinen reinen Debug-Helfer hinzu und bearbeiten Sie ihre SQLite-Datenbank im Browser, während die App weiterläuft.

Viewer öffnen

Was Sie bekommen

Die Live-Bearbeitung funktioniert wie der Database Inspector von Android Studio, aber aus Ihrem Browser. SQLite Viewer sendet jede Änderung an einen winzigen ContentProvider in Ihrer Debug-App, der sie auf der eigenen Datenbank der App ausführt. Die App läuft weiter, und nichts muss gestoppt, kopiert oder neu gestartet werden.

Nur Debug-Builds. Der Helfer erlaubt jedem mit USB-Debugging-Zugriff, Schreibanweisungen auf der Datenbank auszuführen. Registrieren Sie ihn daher nur in src/debug und liefern Sie ihn nie in einem Release-Build aus.

Einrichtung

  1. Helferklasse hinzufügen. Laden Sie SqliteViewerProvider.kt herunter (oder kopieren Sie den Code unten) und legen Sie ihn in Ihrem App-Modul ab, z. B. unter app/src/main/java/com/example/debughelper/. Passen Sie die package-Zeile an den Ordner an.
  2. Nur für Debug-Builds registrieren. Erstellen Sie app/src/debug/AndroidManifest.xml mit dem untenstehenden Provider-Eintrag. Da er im Source-Set debug liegt, enthalten Release-Builds den Eintrag nie, und nichts wird offengelegt.
  3. Optional: Room-Bildschirme aktualisieren. Room bemerkt nur Änderungen über seine eigene Verbindung. Setzen Sie den afterWrite-Hook einmal, damit Ihre LiveData- und Flow-Bildschirme direkt nach einer Live-Bearbeitung aktualisiert werden.
  4. Den Debug-Build ausführen. Installieren Sie Ihren Debug-Build auf dem Telefon und öffnen Sie die App einmal, damit Android den Provider registriert.
  5. Live-Bearbeitung einschalten. Wählen Sie in SQLite Viewer Android, verbinden Sie Ihr Telefon, öffnen Sie die App-Datenbank und aktivieren Sie Live-Bearbeitung. Ein grünes LIVE EDIT-Abzeichen erscheint. Nun wird jede Zeilenbearbeitung, jedes Einfügen, Löschen und jede SQL-Anweisung auch auf die laufende App angewendet.

Debug-Manifest

<?xml version="1.0" encoding="utf-8"?>
<!-- src/debug/AndroidManifest.xml  (debug builds only) -->
<manifest xmlns:android="http://schemas.android.com/apk/res/android">
    <application>
        <provider
            android:name="com.example.debughelper.SqliteViewerProvider"
            android:authorities="${applicationId}.sqliteviewer"
            android:exported="true" />
    </application>
</manifest>

Optionaler Room-Hook

// In your Application class (optional, only if you use Room LiveData / Flow)
override fun onCreate() {
    super.onCreate()
    if (BuildConfig.DEBUG) {
        SqliteViewerProvider.afterWrite = {
            AppDatabase.getInstance(this).invalidationTracker.refreshVersionsAsync()
        }
    }
}

Der Helfer (SqliteViewerProvider.kt)

package com.example.debughelper // use any package, for example your app's own

import android.content.ContentProvider
import android.content.ContentValues
import android.database.Cursor
import android.database.sqlite.SQLiteDatabase
import android.net.Uri
import android.os.Bundle
import android.util.Base64
import org.json.JSONArray

/**
 * DEBUG BUILDS ONLY.
 *
 * Lets SQLite Viewer (https://sqliteviewer.codemasterlk.com) edit this app's databases
 * while the app keeps running. The class can live in src/main, but it is only registered
 * in src/debug/AndroidManifest.xml, so release builds never expose it.
 */
class SqliteViewerProvider : ContentProvider() {

    companion object {
        /** Optional: called after every successful live edit, e.g. to refresh Room observers. */
        @JvmStatic
        var afterWrite: (() -> Unit)? = null

        private val allowedStatement = Regex("""^(INSERT|UPDATE|DELETE|REPLACE|CREATE|DROP|ALTER)\b""", RegexOption.IGNORE_CASE)
        private val leadingNoise = Regex("""^(\s|--[^\n]*\n|/\*.*?\*/)*""", RegexOption.DOT_MATCHES_ALL)
        private val safeName = Regex("""^[A-Za-z0-9._-]+$""")
    }

    private val handles = HashMap<String, SQLiteDatabase>()

    override fun onCreate(): Boolean = true

    override fun call(method: String, arg: String?, extras: Bundle?): Bundle {
        val answer = try {
            when (method) {
                "ping" -> "OK:1"
                "batch" -> "OK:" + runBatch(extras?.getString("db"), arg)
                else -> "ERR:unknown method $method"
            }
        } catch (e: Throwable) {
            "ERR:" + (e.message ?: e.javaClass.simpleName).replace('\n', ' ')
        }
        return Bundle().apply { putString("r", answer) }
    }

    @Synchronized
    private fun database(name: String): SQLiteDatabase {
        handles[name]?.let { if (it.isOpen) return it }

        val file = context!!.getDatabasePath(name)
        require(file.exists()) { "database not found: $name" }

        return SQLiteDatabase.openDatabase(file.path, null, SQLiteDatabase.OPEN_READWRITE)
            .also { handles[name] = it }
    }

    private fun runBatch(name: String?, base64: String?): Int {
        require(name != null && safeName.matches(name)) { "invalid database name" }
        require(!base64.isNullOrEmpty()) { "no statements" }

        val statements = JSONArray(String(Base64.decode(base64, Base64.DEFAULT), Charsets.UTF_8))
        val db = database(name)

        db.beginTransaction()
        try {
            for (i in 0 until statements.length()) {
                val sql = statements.getString(i)
                require(allowedStatement.containsMatchIn(sql.replaceFirst(leadingNoise, ""))) {
                    "statement type not allowed"
                }
                db.execSQL(sql)
            }
            db.setTransactionSuccessful()
        } finally {
            db.endTransaction()
        }

        afterWrite?.invoke()
        return statements.length()
    }

    // Not used: the viewer talks to this provider only through call().
    override fun query(uri: Uri, projection: Array<String>?, selection: String?, selectionArgs: Array<String>?, sortOrder: String?): Cursor? = null
    override fun getType(uri: Uri): String? = null
    override fun insert(uri: Uri, values: ContentValues?): Uri? = null
    override fun delete(uri: Uri, selection: String?, selectionArgs: Array<String>?): Int = 0
    override fun update(uri: Uri, values: ContentValues?, selection: String?, selectionArgs: Array<String>?): Int = 0
}

Was er kann und was nicht

  • Er führt INSERT-, UPDATE-, DELETE-, REPLACE-, CREATE-, DROP- und ALTER-Anweisungen aus. Lesezugriffe, PRAGMAs und VACUUM werden abgelehnt.
  • Jede Bearbeitung wird in einer Transaktion angewendet. Lehnt die App sie ab, zeigt SQLite Viewer den Fehler an und lädt die Daten vom Telefon neu, damit beide synchron bleiben.
  • Sehr große Bearbeitungen (etwa 75 KB SQL) werden nicht live gesendet. Verwenden Sie dafür Auf Telefon übertragen. Dabei wird die gesamte Datenbankdatei ersetzt und die App neu gestartet.
  • Der Datenbankname muss zur Datei im Ordner databases der App passen. Der Helfer verwendet den Paketnamen der Debug-App und funktioniert daher auch mit applicationIdSuffix.
  • Funktioniert bei gleichzeitig laufendem Android Studio, wenn Sie den ADB-Server-Modus des Android-Bereichs verwenden (Anleitung zur Bridge-Einrichtung).

Fehlerbehebung

  • „Live-edit helper not found“: Der Eintrag im Debug-Manifest fehlt, die App wurde nicht neu installiert oder der Paketname weicht ab. Die Provider-Authority muss <Ihr Paket>.sqliteviewer lauten.
  • „database not found“: Öffnen Sie die App einmal, damit sie ihre Datenbank anlegt, und versuchen Sie es dann erneut.
  • Bildschirme aktualisieren sich nicht: Fügen Sie den optionalen Room-Hook von oben hinzu oder öffnen Sie den Bildschirm erneut.
