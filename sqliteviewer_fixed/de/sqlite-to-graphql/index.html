SDL ist keine vollständige API

Ein Datenbankschema beschreibt die Speicherung, GraphQL dagegen einen anwendungsnahen Vertrag. Erzeugtes SDL legt keine Resolver, Authentifizierung, Paginierung, Validierung, Mutationen oder feldbezogene Autorisierung an. Betrachten Sie es als strukturierten ersten Entwurf.

Typzuordnungen prüfen

SQLite-Typen lassen sich nicht perfekt auf GraphQL-Skalare abbilden. Datumswerte können als Text oder Zahlen gespeichert sein, Dezimalzahlen benötigen ggf. einen benutzerdefinierten Skalar, und Binärdaten brauchen eine anwendungsspezifische Darstellung. Benennen Sie technische Datenbankfelder um, wenn ein verständlicherer API-Name passt.

Machen Sie niemals automatisch alle Datenbanktabellen verfügbar. Wählen Sie nur Felder und Operationen aus, auf die Clients zugreifen sollen, und erzwingen Sie die Autorisierung in der API-Schicht.

Beziehungen bewusst einsetzen

Deklarierte Fremdschlüssel können GraphQL-Beziehungen nahelegen, doch das Resolver-Verhalten hängt von Ihrer Server-Implementierung ab. Erwägen Sie Batching und Paginierung, um teure verschachtelte Datenbankzugriffe zu vermeiden.
