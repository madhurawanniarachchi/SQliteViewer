Eine Android-SQLite-Datenbank ansehen

Öffnen Sie eine App-Datenbank, die aus einem Emulator, einem Debug-Build oder einem autorisierten Gerät exportiert wurde, und prüfen Sie sie, ohne einen Desktop-Datenbankbrowser zu installieren.

Android-Datenbank öffnen

Exportieren Sie die Datenbank zuerst legal und sicher

SQLite Viewer öffnet eine Datei, die Sie bereits besitzen; es extrahiert keine Datenbanken aus einem Telefon. Verwenden Sie den Device Explorer von Android Studio, einen Emulator, ein App-Backup oder Ihre eigenen Debug-Werkzeuge, um eine Datenbank zu erhalten, die Sie prüfen dürfen.

Android-App-Datenbanken liegen üblicherweise in einem anwendungsspezifischen Verzeichnis databases und tragen die Endung .db oder keine Endung. Zeigt die Dateiauswahl des Browsers eine Kopie ohne Endung nicht an, benennen Sie die exportierte Datei so um, dass sie auf .db endet.

App-Schema öffnen und prüfen

  1. Ziehen Sie die exportierte Datenbank auf SQLite Viewer.
  2. Suchen Sie in der Tabellen-Seitenleiste nach der Funktion, die Sie debuggen.
  3. Öffnen Sie wahrscheinliche Tabellen und prüfen Sie aktuelle Zeilen.
  4. Nutzen Sie das ER-Diagramm, um Fremdschlüssel und Room-typische Beziehungen zu verstehen.
  5. Führen Sie gezieltes SQL aus, statt durch große Ereignis- oder Cache-Tabellen zu scrollen.
SELECT *
FROM "sync_queue"
ORDER BY "created_at" DESC
LIMIT 0, 100;

Die Datenbank einer Debug-App live über USB ansehen

Wählen Sie in Chrome oder Edge auf dem Desktop in der Symbolleiste Android, verbinden Sie Ihr Telefon mit aktiviertem USB-Debugging und wählen Sie eine Ihrer debugbaren Apps. SQLite Viewer kopiert die Datenbank mit run-as, führt das Write-Ahead-Log zusammen, damit aktuelle Schreibvorgänge enthalten sind, und kann sie während Ihrer Tests alle paar Sekunden aktualisieren. Alles bleibt in Ihrem Browser. Release-Builds sind durch Android geschützt und lassen sich so nicht lesen.

Android Studio hält die USB-Verbindung belegt, daher gibt es im Viewer auch einen ADB-Server-Modus: Laden Sie unter Windows den Bridge-Installer mit einem Klick herunter und starten Sie ihn einmal per Doppelklick. Er richtet einen kleinen Helfer ein, der bei jeder Anmeldung selbst startet, und die Seite teilt den ADB-Server mit Android Studio, sodass beides gleichzeitig funktioniert. Unter macOS und Linux führen Sie stattdessen den Helfer adb-bridge.py aus. Die Seite erkennt die Bridge automatisch. Vollständige Hilfe: ADB-Bridge-Einrichtungsanleitung.

Möchten Sie Daten ändern, ohne die App neu zu starten? Fügen Sie einen kleinen reinen Debug-Helfer hinzu und folgen Sie der Anleitung zur Live-Bearbeitung.

WAL-Datenbanken richtig behandeln

SQLite kann Write-Ahead-Logging verwenden, wodurch die Begleitdateien -wal und -shm entstehen. Wird nur die Hauptdatenbank kopiert, während die App schreibt, können jüngste Transaktionen fehlen. Bevorzugen Sie einen konsistenten Export, der bei geschlossener oder per Checkpoint abgeglichener Datenbank erstellt wurde.

Sensible Daten: App-Datenbanken können personenbezogene Daten, Tokens oder Geschäftsdaten enthalten. Verwenden Sie nur Dateien, die Sie prüfen dürfen, und löschen Sie exportierte Kopien, sobald das Debugging abgeschlossen ist.

Android-Datenbanken bearbeiten

Sie können eine Kopie bearbeiten und herunterladen, doch das Ersetzen einer App-Datenbank kann Schema-Erwartungen verletzen oder den Anwendungszustand beschädigen. Bewahren Sie das Original auf, prüfen Sie Einschränkungen und nutzen Sie möglichst unterstützte Migrations- oder Debug-Werkzeuge.
