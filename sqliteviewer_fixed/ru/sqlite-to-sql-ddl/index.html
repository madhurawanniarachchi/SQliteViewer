Экспорт схемы

Преобразование схемы SQLite в SQL DDL

Получите читаемые определения схемы для документации, проверки, планирования миграции или контроля версий.

Открыть экспорт схемы SQLite

Экспорт SQL DDL из файла базы данных

  1. Откройте базу данных SQLite.
  2. Откройте ER-диаграмму.
  3. Выберите SQL DDL в качестве формата экспорта.
  4. Экспортируйте и сохраните полученный текст схемы.

Результат описывает структуру базы данных, а не данные таблиц. Он включает определения сущностей, объявленные типы столбцов и сведения о ключах, которые можно получить из метаданных схемы SQLite.

Пример результата

CREATE TABLE "orders" (
  "id" INTEGER PRIMARY KEY,
  "customer_id" INTEGER NOT NULL,
  "created_at" TEXT,
  FOREIGN KEY ("customer_id") REFERENCES "customers" ("id")
);

Для чего нужен SQL DDL

  • Проверка схемы базы данных при код-ревью.
  • Хранение изменений структуры в системе контроля версий.
  • Документирование таблиц без раскрытия рабочих данных.
  • Подготовка миграции в другую систему баз данных.
  • Сравнение ожидаемых и фактических определений таблиц.
Замечание о миграции: синтаксис и сродство типов SQLite отличаются от PostgreSQL, MySQL и SQL Server. Считайте экспортированный DDL надёжным описанием схемы SQLite, а затем адаптируйте типы, поведение автоинкремента, кавычки и ограничения под целевую СУБД.

Экспорт схемы и сохранение базы данных

SQL DDL содержит только структуру. Если нужна база данных со строками и локальными изменениями, используйте Сохранить БД. Если нужны строки в переносимом текстовом формате, воспользуйтесь экспортом результатов.
