Преобразование SQLite в GraphQL SDL

Преобразуйте сущности базы данных в читаемые определения типов GraphQL, а затем адаптируйте их под нужды приложения.

Открыть экспорт в GraphQL SDL

Создание схемы

  1. Откройте базу данных SQLite.
  2. Изучите её сущности на ER-диаграмме.
  3. Выберите GraphQL SDL в качестве формата экспорта.
  4. Экспортируйте определения типов и просмотрите их в проекте API.
type Customer {
  id: Int!
  name: String
  orders: [Order!]
}

type Order {
  id: Int!
  customerId: Int!
}

SDL — это не готовый API

Схема базы данных описывает хранение, а GraphQL — контракт, обращённый к приложению. Созданный SDL не создаёт резолверы, аутентификацию, пагинацию, валидацию, мутации и авторизацию на уровне полей. Считайте его структурированным первым черновиком.

Проверьте сопоставление типов

Типы SQLite не идеально соответствуют скалярам GraphQL. Даты могут храниться как текст или числа, для десятичных чисел может понадобиться собственный скаляр, а двоичным данным нужно представление, специфичное для приложения. Переименуйте технические поля базы данных, если для API подходит более понятное имя.

Никогда не открывайте автоматически все таблицы базы данных. Выбирайте только те поля и операции, к которым должны иметь доступ клиенты, и применяйте авторизацию на уровне API.

Используйте связи осознанно

Объявленные внешние ключи могут подсказать связи GraphQL, но поведение резолверов зависит от реализации вашего сервера. Рассмотрите пакетную обработку и пагинацию, чтобы избежать дорогих вложенных обращений к базе данных.
