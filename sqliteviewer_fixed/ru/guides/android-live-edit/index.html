Отладка Android в реальном времени

Редактирование базы данных приложения Android без перезапуска приложения

Добавьте в приложение небольшой отладочный помощник и редактируйте его базу данных SQLite из браузера, пока приложение продолжает работать.

Открыть просмотрщик

Что вы получаете

Редактирование в реальном времени работает как Database Inspector в Android Studio, но из браузера. SQLite Viewer отправляет каждое изменение небольшому ContentProvider внутри вашего отладочного приложения, и тот выполняет его в собственной базе данных приложения. Приложение продолжает работать, и ничего не нужно останавливать, копировать или перезапускать.

Только отладочные сборки. Помощник позволяет любому, у кого есть доступ к отладке по USB, выполнять операторы записи в базе данных, поэтому регистрируйте его только в src/debug и никогда не включайте в релизную сборку.

Настройка

  1. Добавьте класс-помощник. Скачайте SqliteViewerProvider.kt (или скопируйте код ниже) в модуль приложения, например в app/src/main/java/com/example/debughelper/. Измените строку package, чтобы она соответствовала папке.
  2. Зарегистрируйте его только для отладочных сборок. Создайте app/src/debug/AndroidManifest.xml с приведённой ниже записью провайдера. Поскольку он находится в наборе исходников debug, релизные сборки никогда не содержат эту запись, и ничего не раскрывается.
  3. По желанию: обновляйте экраны Room. Room замечает только изменения, сделанные через его собственное соединение. Один раз задайте хук afterWrite, чтобы экраны на LiveData и Flow обновлялись сразу после редактирования в реальном времени.
  4. Запустите отладочную сборку. Установите отладочную сборку на телефон и один раз откройте приложение, чтобы Android зарегистрировал провайдер.
  5. Включите редактирование в реальном времени. В SQLite Viewer выберите Android, подключите телефон, откройте базу данных приложения и отметьте Live edit. Появится зелёный значок LIVE EDIT. Теперь каждое редактирование строки, вставка, удаление и SQL-оператор также применяются к работающему приложению.

Отладочный манифест

<?xml version="1.0" encoding="utf-8"?>
<!-- src/debug/AndroidManifest.xml  (debug builds only) -->
<manifest xmlns:android="http://schemas.android.com/apk/res/android">
    <application>
        <provider
            android:name="com.example.debughelper.SqliteViewerProvider"
            android:authorities="${applicationId}.sqliteviewer"
            android:exported="true" />
    </application>
</manifest>

Необязательный хук Room

// In your Application class (optional, only if you use Room LiveData / Flow)
override fun onCreate() {
    super.onCreate()
    if (BuildConfig.DEBUG) {
        SqliteViewerProvider.afterWrite = {
            AppDatabase.getInstance(this).invalidationTracker.refreshVersionsAsync()
        }
    }
}

Помощник (SqliteViewerProvider.kt)

package com.example.debughelper // use any package, for example your app's own

import android.content.ContentProvider
import android.content.ContentValues
import android.database.Cursor
import android.database.sqlite.SQLiteDatabase
import android.net.Uri
import android.os.Bundle
import android.util.Base64
import org.json.JSONArray

/**
 * DEBUG BUILDS ONLY.
 *
 * Lets SQLite Viewer (https://sqliteviewer.codemasterlk.com) edit this app's databases
 * while the app keeps running. The class can live in src/main, but it is only registered
 * in src/debug/AndroidManifest.xml, so release builds never expose it.
 */
class SqliteViewerProvider : ContentProvider() {

    companion object {
        /** Optional: called after every successful live edit, e.g. to refresh Room observers. */
        @JvmStatic
        var afterWrite: (() -> Unit)? = null

        private val allowedStatement = Regex("""^(INSERT|UPDATE|DELETE|REPLACE|CREATE|DROP|ALTER)\b""", RegexOption.IGNORE_CASE)
        private val leadingNoise = Regex("""^(\s|--[^\n]*\n|/\*.*?\*/)*""", RegexOption.DOT_MATCHES_ALL)
        private val safeName = Regex("""^[A-Za-z0-9._-]+$""")
    }

    private val handles = HashMap<String, SQLiteDatabase>()

    override fun onCreate(): Boolean = true

    override fun call(method: String, arg: String?, extras: Bundle?): Bundle {
        val answer = try {
            when (method) {
                "ping" -> "OK:1"
                "batch" -> "OK:" + runBatch(extras?.getString("db"), arg)
                else -> "ERR:unknown method $method"
            }
        } catch (e: Throwable) {
            "ERR:" + (e.message ?: e.javaClass.simpleName).replace('\n', ' ')
        }
        return Bundle().apply { putString("r", answer) }
    }

    @Synchronized
    private fun database(name: String): SQLiteDatabase {
        handles[name]?.let { if (it.isOpen) return it }

        val file = context!!.getDatabasePath(name)
        require(file.exists()) { "database not found: $name" }

        return SQLiteDatabase.openDatabase(file.path, null, SQLiteDatabase.OPEN_READWRITE)
            .also { handles[name] = it }
    }

    private fun runBatch(name: String?, base64: String?): Int {
        require(name != null && safeName.matches(name)) { "invalid database name" }
        require(!base64.isNullOrEmpty()) { "no statements" }

        val statements = JSONArray(String(Base64.decode(base64, Base64.DEFAULT), Charsets.UTF_8))
        val db = database(name)

        db.beginTransaction()
        try {
            for (i in 0 until statements.length()) {
                val sql = statements.getString(i)
                require(allowedStatement.containsMatchIn(sql.replaceFirst(leadingNoise, ""))) {
                    "statement type not allowed"
                }
                db.execSQL(sql)
            }
            db.setTransactionSuccessful()
        } finally {
            db.endTransaction()
        }

        afterWrite?.invoke()
        return statements.length()
    }

    // Not used: the viewer talks to this provider only through call().
    override fun query(uri: Uri, projection: Array<String>?, selection: String?, selectionArgs: Array<String>?, sortOrder: String?): Cursor? = null
    override fun getType(uri: Uri): String? = null
    override fun insert(uri: Uri, values: ContentValues?): Uri? = null
    override fun delete(uri: Uri, selection: String?, selectionArgs: Array<String>?): Int = 0
    override fun update(uri: Uri, values: ContentValues?, selection: String?, selectionArgs: Array<String>?): Int = 0
}

Что он может и чего не может

  • Он выполняет операторы INSERT, UPDATE, DELETE, REPLACE, CREATE, DROP и ALTER. Чтение, PRAGMA и VACUUM отклоняются.
  • Каждое изменение применяется в транзакции. Если приложение его отклоняет, SQLite Viewer показывает ошибку и перезагружает данные с телефона, чтобы обе стороны оставались синхронизированными.
  • Очень большие изменения (около 75 КБ SQL) в реальном времени не отправляются. Для них используйте Отправить на телефон. Эта функция заменяет весь файл базы данных и перезапускает приложение.
  • Имя базы данных должно совпадать с файлом в папке databases приложения. Помощник использует имя пакета отладочного приложения, поэтому работает и с applicationIdSuffix.
  • Работает одновременно с Android Studio, если использовать режим сервера ADB на панели Android (руководство по настройке моста).

Устранение неполадок

  • «Live-edit helper not found»: отсутствует запись в отладочном манифесте, приложение не было переустановлено или имя пакета отличается. Authority провайдера должен быть <ваш пакет>.sqliteviewer.
  • «database not found»: один раз откройте приложение, чтобы оно создало свою базу данных, и повторите попытку.
  • Экраны не обновляются: добавьте необязательный хук Room, описанный выше, или заново откройте экран.
