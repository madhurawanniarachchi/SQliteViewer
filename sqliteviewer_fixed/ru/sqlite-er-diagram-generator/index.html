Создание ER-диаграммы из SQLite

Превратите незнакомую базу данных в понятную карту таблиц, столбцов, типов, первичных ключей и связей внешних ключей.

Открыть инструмент ER-диаграмм

Создайте диаграмму

  1. Откройте базу данных SQLite в просмотрщике.
  2. Выберите ER-диаграмма на боковой панели таблиц.
  3. Нажмите Вписать, чтобы все сущности поместились в области диалога.
  4. Изучите имена столбцов, типы данных SQLite и маркеры ключей каждой сущности.

Линии связей строятся по внешним ключам, объявленным в SQLite. Если логическая связь не задана ограничением внешнего ключа, инструмент чтения схемы не сможет надёжно определить её только по именам столбцов.

Как читать результат

  • PK обозначает столбец первичного ключа, однозначно идентифицирующий строку.
  • FK обозначает столбец, ссылающийся на ключ в другой таблице.
  • Типы столбцов показывают объявленный тип SQLite. Из-за гибкой системы типов SQLite хранимые значения иногда могут отличаться от этого объявления.
  • Соединительные линии показывают сущности, на которые ссылаются, и сущности, которые ссылаются.
Диаграмма наиболее полезна, когда в базе данных последовательно объявлены первичные и внешние ключи. Отсутствующие линии чаще означают отсутствие ограничений, а не проблему отображения.

Экспорт схемы

После просмотра диаграммы экспортируйте схему в SQL DDL, DBML, Mermaid или GraphQL SDL. SQL DDL ближе всего к исходному определению базы данных. DBML и Mermaid удобны для документации. GraphQL SDL — отправная точка для модели API, которая может потребовать доработки под приложение.

Полезные вопросы для проверки

Ищите таблицы без первичных ключей, внешние ключи, указывающие на неожиданные сущности, непоследовательные имена, столбцы с допустимым NULL, которые должны быть обязательными, и связующие таблицы, представляющие связи «многие ко многим». Эти проверки помогают, когда вы получаете в наследство базу данных приложения или планируете миграцию.
