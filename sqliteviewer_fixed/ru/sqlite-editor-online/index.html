Редактирование строк с защитой по первичному ключу

Откройте базу данных и выберите таблицу. Если у таблицы есть пригодный первичный ключ, в результатах появятся действия для редактирования и удаления отдельных строк. Редактор использует значения первичного ключа, чтобы точно найти нужную строку, а не полагается на её положение на экране.

  1. Выберите Изменить у строки.
  2. Измените нужные значения полей. Используйте значение null, если столбец это допускает.
  3. Сохраните строку и проверьте обновлённый результат.
  4. По завершении выберите Сохранить БД, чтобы скачать базу данных.
Важно: изменения вносятся в базу данных, находящуюся в памяти браузера. Они не перезаписывают исходный файл автоматически. Скачайте актуальную базу данных до закрытия страницы.

SQL для массовых изменений

Рабочая область запросов также поддерживает операторы записи SQLite. Например:

UPDATE "products"
SET "active" = 0
WHERE "last_order_at" < '2025-01-01';

Внимательно проверьте условие WHERE перед выполнением обновления или удаления. Хорошая практика — сначала выполнить то же условие как SELECT, убедиться в затронутых строках и только потом выполнять запрос на запись.

Что может помешать редактированию строк?

Безопасные действия со строками требуют, чтобы просмотрщик надёжно идентифицировал записи. Таблицы без первичных ключей могут отображаться в интерфейсе строк как доступные только для чтения. Представления, вычисляемые результаты, соединения и агрегирующие запросы, как правило, нельзя надёжно сопоставить с одной исходной строкой, хотя их можно просматривать и экспортировать.

Скачайте готовую базу данных

Действие «Сохранить БД» экспортирует текущее состояние базы данных SQLite, включая успешные правки строк и запросы на запись. Храните оригинал как резервную копию, пока не проверите скачанный файл в приложении, которое его использует.
