Qué incluye la conversión

La exportación describe tablas, nombres de columna, tipos de datos declarados en SQLite, claves primarias y relaciones de clave externa declaradas. Da a las herramientas de diseño estructura suficiente para representar un modelo útil sin exponer las filas de las tablas.

Table orders {
  id integer [pk]
  customer_id integer [not null]
  created_at text
}

Ref: orders.customer_id > customers.id

¿Por qué usar DBML?

DBML es más fácil de revisar que un binario de base de datos y se centra más en el modelado de datos que en SQL ejecutable. Los equipos lo usan para discutir esquemas, crear diagramas, documentar relaciones y planificar cambios antes de escribir migraciones.

DBML es una representación de diseño, no una copia de seguridad byte a byte de la base de datos. Conserva el archivo SQLite original y usa Guardar BD cuando necesites una base de datos funcional con sus datos.

Revisa el modelo generado

SQLite permite declaraciones de tipo flexibles y los esquemas pueden omitir claves externas. Comprueba los tipos personalizados, las restricciones compuestas, las columnas generadas, los índices y las relaciones que solo existen en el código de la aplicación. Añade anotaciones de diseño tras la exportación cuando sea necesario.
