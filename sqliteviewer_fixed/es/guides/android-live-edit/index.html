Depuración en vivo de Android

Edita en vivo la base de datos de una app Android sin reiniciarla

Añade un pequeño ayudante solo para depuración a tu app y edita su base de datos SQLite desde el navegador mientras la app sigue ejecutándose.

Abrir el visor

Qué obtienes

La edición en vivo funciona como el Database Inspector de Android Studio, pero desde tu navegador. SQLite Viewer envía cada cambio a un pequeño ContentProvider dentro de tu app de depuración, que lo ejecuta sobre la base de datos de la propia app. La app sigue ejecutándose y no hay que detener, copiar ni reiniciar nada.

Solo compilaciones de depuración. El ayudante permite que cualquiera con acceso de depuración USB ejecute sentencias de escritura en la base de datos, así que regístralo únicamente en src/debug y nunca lo incluyas en una compilación de lanzamiento.

Configúralo

  1. Añade la clase ayudante. Descarga SqliteViewerProvider.kt (o copia el código de abajo) en el módulo de tu app, por ejemplo en app/src/main/java/com/example/debughelper/. Cambia la línea package para que coincida con la carpeta.
  2. Regístralo solo para compilaciones de depuración. Crea app/src/debug/AndroidManifest.xml con la entrada del proveedor que se muestra abajo. Como está en el conjunto de fuentes debug, las compilaciones de lanzamiento nunca contienen la entrada y no se expone nada.
  3. Opcional: actualiza las pantallas de Room. Room solo detecta los cambios realizados a través de su propia conexión. Configura una vez el hook afterWrite para que tus pantallas con LiveData y Flow se actualicen justo después de una edición en vivo.
  4. Ejecuta la compilación de depuración. Instala tu compilación de depuración en el teléfono y abre la app una vez para que Android registre el proveedor.
  5. Activa la edición en vivo. En SQLite Viewer elige Android, conecta tu teléfono, abre la base de datos de la app y marca Edición en vivo. Aparece una insignia verde EDICIÓN EN VIVO. A partir de ahora, cada edición de fila, inserción, eliminación y sentencia SQL que ejecutes también se aplica a la app en ejecución.

Manifiesto de depuración

<?xml version="1.0" encoding="utf-8"?>
<!-- src/debug/AndroidManifest.xml  (debug builds only) -->
<manifest xmlns:android="http://schemas.android.com/apk/res/android">
    <application>
        <provider
            android:name="com.example.debughelper.SqliteViewerProvider"
            android:authorities="${applicationId}.sqliteviewer"
            android:exported="true" />
    </application>
</manifest>

Hook opcional de Room

// In your Application class (optional, only if you use Room LiveData / Flow)
override fun onCreate() {
    super.onCreate()
    if (BuildConfig.DEBUG) {
        SqliteViewerProvider.afterWrite = {
            AppDatabase.getInstance(this).invalidationTracker.refreshVersionsAsync()
        }
    }
}

El ayudante (SqliteViewerProvider.kt)

package com.example.debughelper // use any package, for example your app's own

import android.content.ContentProvider
import android.content.ContentValues
import android.database.Cursor
import android.database.sqlite.SQLiteDatabase
import android.net.Uri
import android.os.Bundle
import android.util.Base64
import org.json.JSONArray

/**
 * DEBUG BUILDS ONLY.
 *
 * Lets SQLite Viewer (https://sqliteviewer.codemasterlk.com) edit this app's databases
 * while the app keeps running. The class can live in src/main, but it is only registered
 * in src/debug/AndroidManifest.xml, so release builds never expose it.
 */
class SqliteViewerProvider : ContentProvider() {

    companion object {
        /** Optional: called after every successful live edit, e.g. to refresh Room observers. */
        @JvmStatic
        var afterWrite: (() -> Unit)? = null

        private val allowedStatement = Regex("""^(INSERT|UPDATE|DELETE|REPLACE|CREATE|DROP|ALTER)\b""", RegexOption.IGNORE_CASE)
        private val leadingNoise = Regex("""^(\s|--[^\n]*\n|/\*.*?\*/)*""", RegexOption.DOT_MATCHES_ALL)
        private val safeName = Regex("""^[A-Za-z0-9._-]+$""")
    }

    private val handles = HashMap<String, SQLiteDatabase>()

    override fun onCreate(): Boolean = true

    override fun call(method: String, arg: String?, extras: Bundle?): Bundle {
        val answer = try {
            when (method) {
                "ping" -> "OK:1"
                "batch" -> "OK:" + runBatch(extras?.getString("db"), arg)
                else -> "ERR:unknown method $method"
            }
        } catch (e: Throwable) {
            "ERR:" + (e.message ?: e.javaClass.simpleName).replace('\n', ' ')
        }
        return Bundle().apply { putString("r", answer) }
    }

    @Synchronized
    private fun database(name: String): SQLiteDatabase {
        handles[name]?.let { if (it.isOpen) return it }

        val file = context!!.getDatabasePath(name)
        require(file.exists()) { "database not found: $name" }

        return SQLiteDatabase.openDatabase(file.path, null, SQLiteDatabase.OPEN_READWRITE)
            .also { handles[name] = it }
    }

    private fun runBatch(name: String?, base64: String?): Int {
        require(name != null && safeName.matches(name)) { "invalid database name" }
        require(!base64.isNullOrEmpty()) { "no statements" }

        val statements = JSONArray(String(Base64.decode(base64, Base64.DEFAULT), Charsets.UTF_8))
        val db = database(name)

        db.beginTransaction()
        try {
            for (i in 0 until statements.length()) {
                val sql = statements.getString(i)
                require(allowedStatement.containsMatchIn(sql.replaceFirst(leadingNoise, ""))) {
                    "statement type not allowed"
                }
                db.execSQL(sql)
            }
            db.setTransactionSuccessful()
        } finally {
            db.endTransaction()
        }

        afterWrite?.invoke()
        return statements.length()
    }

    // Not used: the viewer talks to this provider only through call().
    override fun query(uri: Uri, projection: Array<String>?, selection: String?, selectionArgs: Array<String>?, sortOrder: String?): Cursor? = null
    override fun getType(uri: Uri): String? = null
    override fun insert(uri: Uri, values: ContentValues?): Uri? = null
    override fun delete(uri: Uri, selection: String?, selectionArgs: Array<String>?): Int = 0
    override fun update(uri: Uri, values: ContentValues?, selection: String?, selectionArgs: Array<String>?): Int = 0
}

Qué puede y qué no puede hacer

  • Ejecuta sentencias INSERT, UPDATE, DELETE, REPLACE, CREATE, DROP y ALTER. Las lecturas, los PRAGMA y VACUUM se rechazan.
  • Cada edición se aplica en una transacción. Si la app la rechaza, SQLite Viewer muestra el error y recarga los datos desde el teléfono para que ambos sigan sincronizados.
  • Las ediciones muy grandes (unos 75 KB de SQL) no se envían en vivo. Usa Enviar al teléfono para esas. Reemplaza todo el archivo de la base de datos y reinicia la app.
  • El nombre de la base de datos debe coincidir con el archivo de la carpeta databases de la app. El ayudante usa el nombre de paquete de la app de depuración, así que también funciona con applicationIdSuffix.
  • Funciona con Android Studio ejecutándose a la vez cuando usas el modo servidor ADB del panel de Android (guía de configuración del puente).

Solución de problemas

  • «No se encontró el ayudante de edición en vivo»: falta la entrada del manifiesto de depuración, la app no se reinstaló o el nombre del paquete es distinto. La autoridad del proveedor debe ser <tu paquete>.sqliteviewer.
  • «No se encontró la base de datos»: abre la app una vez para que cree su base de datos y vuelve a intentarlo.
  • Las pantallas no se actualizan: añade el hook opcional de Room de arriba o vuelve a abrir la pantalla.
