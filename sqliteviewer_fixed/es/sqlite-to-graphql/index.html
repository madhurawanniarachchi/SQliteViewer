SDL no es una API completa

Un esquema de base de datos describe almacenamiento, mientras que GraphQL describe un contrato orientado a la aplicación. El SDL generado no crea resolvers, autenticación, paginación, validación, mutaciones ni autorización a nivel de campo. Trátalo como un primer borrador estructurado.

Revisa las asignaciones de tipos

Los tipos de SQLite no se corresponden perfectamente con los escalares de GraphQL. Las fechas pueden almacenarse como texto o números, los decimales pueden necesitar un escalar personalizado y los datos binarios requieren una representación específica de la aplicación. Renombra los campos técnicos de la base de datos cuando un nombre de API más claro sea apropiado.

Nunca expongas automáticamente todas las tablas de la base de datos. Selecciona solo los campos y las operaciones a los que los clientes deben acceder y aplica la autorización en la capa de API.

Usa las relaciones con criterio

Las claves externas declaradas pueden sugerir relaciones GraphQL, pero el comportamiento de los resolvers depende de la implementación de tu servidor. Considera el procesamiento por lotes y la paginación para evitar accesos anidados costosos a la base de datos.
