التصحيح المباشر لـ Android

إعداد جسر ADB (يعمل جنبًا إلى جنب مع Android Studio)

مساعد صغير واحد يتيح لـ SQLite Viewer وAndroid Studio استخدام هاتفك في الوقت نفسه. نزّله وضعه في مكانه واجعله يبدأ تلقائيًا وانتهى الأمر.

افتح العارض

هل أحتاج إلى الجسر؟

غالبًا لا. يمكن لـ SQLite Viewer التواصل مع هاتفك مباشرة عبر USB (وضع USB المباشر في Chrome أو Edge) دون تثبيت أي شيء. الجسر مخصص لحالة واحدة: Android Studio (أو أداة ADB أخرى) يستخدم الهاتف بالفعل. لا يمكن لبرنامج واحد فقط امتلاك اتصال USB، لذا يتيح الجسر لـ SQLite Viewer مشاركة خادم ADB الخاص بـ Android Studio. عندها يعمل الاثنان معًا.

USB مباشرخادم ADB (الجسر)
هل أثبّت شيئًا؟لانعم، مرة واحدة (نقرة واحدة على Windows)
هل يعمل مع فتح Android Studio؟لا، يجب إغلاقهنعم
المتصفحChrome أو Edge على سطح المكتبأي متصفح حديث
هل يلزم ADB على الكمبيوتر؟لانعم (Android Studio أو Platform Tools)

Windows: مثبّت بنقرة واحدة

  1. نزّل المثبّت. في SQLite Viewer افتح Live Android واختر خادم ADB وانقر تنزيل المثبّت (Windows).
  2. احتفظ بالملف. قد يقول Chrome إنه لا يمكن التحقق من الملف. اختر الاحتفاظ (أو تنزيل ملف غير موثّق). الملف نص عادي، لذا يمكنك فتحه في المفكرة لقراءة ما يفعله بالضبط.
  3. شغّله مرة واحدة. انقر نقرًا مزدوجًا على Install-ADB-Bridge.cmd. إذا ظهرت رسالة Windows protected your PC، فانقر More info ثم Run anyway.
  4. عد إلى الصفحة. يبني المثبّت الجسر على جهازك ويجعله يبدأ تلقائيًا عند كل تسجيل دخول ويشغّله. يلاحظه SQLite Viewer خلال بضع ثوانٍ. انقر الاتصال عبر الجسر.

يُثبَّت الجسر في %LOCALAPPDATA%\SQLiteViewerBridge ويشغّله اختصار في مجلد بدء التشغيل عند تسجيل الدخول. لإزالته، شغّل uninstall.cmd من ذلك المجلد.

أي نظام: الإعداد باستخدام Python

  1. ثبّت Python 3. نزّله من python.org. على Windows حدّد Add Python to PATH في المثبّت. تحتوي معظم أنظمة Linux على python3 بالفعل. لا يتضمنه macOS افتراضيًا: عند كتابة python3 أول مرة يعرض macOS تثبيت Command Line Tools من Apple (اقبل ذلك)، أو يمكنك استخدام مثبّت python.org.
  2. نزّل الملف. نزّل adb-bridge.py. يحفظه متصفحك في مجلد التنزيلات. وإذا انتهى بـ .txt فأعد تسميته إلى adb-bridge.py.
  3. انسخه إلى مكانه الدائم. افتح نافذة طرفية (أي مجلد يصلح، فالأوامر تستخدم مسارات كاملة) وشغّل الأمر الخاص بنظامك. ينشئ المجلد وينسخ الملف إليه. وإذا حفظ متصفحك الملف في مكان غير التنزيلات، فغيّر ذلك الجزء من الأمر.
  4. اجعله يبدأ تلقائيًا. شغّل الأمر الخاص بنظامك. يُعدّ إدخال البدء عند تسجيل الدخول للملف الذي نسخته ويشغّل الجسر الآن.
  5. اتصل. عد إلى SQLite Viewer. يجد الجسر بنفسه. انقر الاتصال عبر الجسر.

الخطوة 3: انسخ الملف (شغّلها مرة واحدة)

Windows (PowerShell؛ اضغط مفتاح Windows واكتب powershell ثم Enter):

New-Item -ItemType Directory -Force "$env:LOCALAPPDATA\SQLiteViewerBridgePython" | Out-Null; Copy-Item "$env:USERPROFILE\Downloads\adb-bridge.py" "$env:LOCALAPPDATA\SQLiteViewerBridgePython\adb-bridge.py"

Windows (موجه الأوامر؛ اضغط مفتاح Windows واكتب cmd ثم Enter):

mkdir "%LOCALAPPDATA%\SQLiteViewerBridgePython" & copy "%USERPROFILE%\Downloads\adb-bridge.py" "%LOCALAPPDATA%\SQLiteViewerBridgePython\adb-bridge.py"

macOS (Terminal):

mkdir -p "$HOME/Library/Application Support/SQLiteViewerBridge" && cp "$HOME/Downloads/adb-bridge.py" "$HOME/Library/Application Support/SQLiteViewerBridge/adb-bridge.py"

Linux:

mkdir -p "$HOME/.local/share/sqliteviewer-bridge" && cp "$HOME/Downloads/adb-bridge.py" "$HOME/.local/share/sqliteviewer-bridge/adb-bridge.py"

الخطوة 4: اجعله يبدأ تلقائيًا عند تسجيل الدخول (شغّلها مرة واحدة)

Windows (PowerShell):

python "$env:LOCALAPPDATA\SQLiteViewerBridgePython\adb-bridge.py" --add-to-startup

Windows (موجه الأوامر):

python "%LOCALAPPDATA%\SQLiteViewerBridgePython\adb-bridge.py" --add-to-startup

macOS:

python3 "$HOME/Library/Application Support/SQLiteViewerBridge/adb-bridge.py" --add-to-startup

Linux:

python3 "$HOME/.local/share/sqliteviewer-bridge/adb-bridge.py" --add-to-startup

على Windows ينشئ هذا اختصارًا مخفيًا في مجلد بدء التشغيل، وعلى macOS ينشئ Launch Agent، وعلى Linux ينشئ خدمة مستخدم systemd (أو إدخال بدء تلقائي لسطح المكتب). ولا يحتاج أي منها إلى صلاحيات المسؤول. أبقِ الملف في مكانه؛ وإذا نقلته فشغّل الأمر مرة أخرى.

على عجل؟ أمر واحد ينفّذ الخطوتين 3 و4

افتح نافذة طرفية في المجلد الذي نزّلت الملف إليه وشغّل:

python adb-bridge.py --install      # Windows
python3 adb-bridge.py --install     # macOS and Linux

هل تفضّل إضافته إلى بدء التشغيل يدويًا؟

Windows: اضغط Win + R واكتب shell:startup ثم Enter. في المجلد الذي يُفتح، انقر بزر الماوس الأيمن واختر New → Shortcut وعيّن الموقع إلى:

pythonw "%LOCALAPPDATA%\SQLiteViewerBridgePython\adb-bridge.py"

سمِّه SQLite Viewer ADB Bridge. استخدام pythonw بدل python يمنع ظهور النافذة السوداء. سجّل الخروج ثم الدخول، أو انقر الاختصار نقرًا مزدوجًا لتشغيله الآن.

macOS: ينشئ الأمر أعلاه ~/Library/LaunchAgents/com.sqliteviewer.adbbridge.plist. Linux: ينشئ ~/.config/systemd/user/sqliteviewer-bridge.service (أو ~/.config/autostart/sqliteviewer-bridge.desktop). يمكن كتابة هذه الملفات يدويًا، لكن الأمر أكثر أمانًا.

تحقق منه وأوقفه وأزله

python adb-bridge.py --status                  # is it running?
python adb-bridge.py --remove-from-startup      # stop starting at sign-in (keeps the file)
python adb-bridge.py --uninstall                # stop it and delete everything
# add the full path to the file if you are not in its folder, as in the commands above

هل لدي ADB؟ ثبّته إن لم يكن موجودًا

يمرّر الجسر الطلبات إلى ADB (Android Platform Tools). يتضمنه Android Studio بالفعل، فإن كنت تستخدم Android Studio يمكنك تخطي هذا القسم. للتحقق افتح نافذة طرفية وشغّل adb version. وإذا لم يتعرف النظام على الأمر، فثبّت ADB بأحد الأوامر أدناه. كما يخبرك SQLite Viewer عندما يعمل الجسر ولا يجد ADB. يبحث الجسر عن ADB في PATH وفي مجلدات Android Studio وwinget وHomebrew والتنزيل اليدوي المعتادة، فلا تحتاج إلى تغيير PATH، ويشغّل لك خادم ADB.

Windows

الأسهل (Windows 10 و11، PowerShell أو موجه الأوامر):

winget install --id Google.PlatformTools -e

لا يوجد winget؟ نزّله مباشرة (PowerShell):

Invoke-WebRequest https://dl.google.com/android/repository/platform-tools-latest-windows.zip -OutFile "$env:TEMP\pt.zip"; Expand-Archive "$env:TEMP\pt.zip" "$env:LOCALAPPDATA\Android\Sdk" -Force; Remove-Item "$env:TEMP\pt.zip"

الأمر نفسه في موجه الأوامر:

powershell -NoProfile -Command "Invoke-WebRequest https://dl.google.com/android/repository/platform-tools-latest-windows.zip -OutFile \"$env:TEMP\pt.zip\"; Expand-Archive \"$env:TEMP\pt.zip\" \"$env:LOCALAPPDATA\Android\Sdk\" -Force; Remove-Item \"$env:TEMP\pt.zip\""

تحقق من نجاح العملية (PowerShell):

& "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe" version

macOS

باستخدام Homebrew:

brew install --cask android-platform-tools

بدون Homebrew:

mkdir -p "$HOME/Library/Android/sdk" && curl -L -o /tmp/pt.zip https://dl.google.com/android/repository/platform-tools-latest-darwin.zip && unzip -o /tmp/pt.zip -d "$HOME/Library/Android/sdk" && rm /tmp/pt.zip

Linux

Debian وUbuntu وMint:

sudo apt install adb

Fedora:

sudo dnf install android-tools

Arch وManjaro:

sudo pacman -S android-tools

أي توزيعة أخرى:

mkdir -p "$HOME/Android/Sdk" && curl -L -o /tmp/pt.zip https://dl.google.com/android/repository/platform-tools-latest-linux.zip && unzip -o /tmp/pt.zip -d "$HOME/Android/Sdk" && rm /tmp/pt.zip

ثم جهّز الهاتف

  1. على الهاتف افتح Settings → About phone وانقر Build number سبع مرات.
  2. افتح Settings → Developer options وفعّل USB debugging.
  3. وصِل الهاتف وانقر Allow في الرسالة. ينبغي أن يعرضه الأمر adb devices بالحالة device.

هل أحتاج إلى ضبط أي شيء؟

لا. لا يقبل الجسر إلا الاتصالات القادمة من موقع SQLite Viewer، ويستمع على جهازك أنت فقط (127.0.0.1)، ولا يمرّر إلا إلى خادم ADB على الجهاز نفسه. ولا يُخزَّن أو يُرسَل أي شيء إلى أي مكان آخر.

تحتاج إلى إعداد في حالتين فقط:

  • تستخدم SQLite Viewer من عنوان مختلف (نسختك الخاصة، أو localhost أثناء التطوير). اسمح بذلك العنوان في الأوامر نفسها:
python "%LOCALAPPDATA%\SQLiteViewerBridgePython\adb-bridge.py" --add-to-startup --allow-origin https://your-address.example
  • المنفذ 5038 مستخدم بالفعل. استخدم منفذًا آخر ثم أدخل المنفذ نفسه ضمن Advanced في لوحة Android:
python "%LOCALAPPDATA%\SQLiteViewerBridgePython\adb-bridge.py" --add-to-startup --port 5040

تُحفظ العناوين المسموح بها في ملف اسمه origins.txt (عنوان في كل سطر) بجانب الجسر: على Windows %LOCALAPPDATA%\SQLiteViewerBridge (المثبّت) أو %LOCALAPPDATA%\SQLiteViewerBridgePython (Python)، وعلى macOS ~/Library/Application Support/SQLiteViewerBridge، وعلى Linux ~/.local/share/sqliteviewer-bridge.

استكشاف الأخطاء

  • «The bridge is not running on this computer»: شغّل المثبّت أو الأوامر أعلاه، أو سجّل الخروج ثم الدخول. ثم أعد فتح لوحة Android.
  • ليس لدي Python: على Windows لا تحتاج إليه، استخدم المثبّت بنقرة واحدة أعلاه. وإلا فثبّت Python 3 من python.org (على Windows: حدّد Add Python to PATH)، أو على macOS اقبل عرض تثبيت Command Line Tools. ثم شغّل الأوامر مرة أخرى.
  • الأمر python غير معروف أو يفتح Microsoft Store (Windows): لم يُثبَّت Python بعد أو فاتك خيار PATH. ثبّته من python.org أو استبدل python بـ py في الأوامر. ويمكنك أيضًا إيقاف اختصار المتجر من Settings → Apps → Advanced app settings → App execution aliases.
  • يقول أمر النسخ إنه لا يمكن العثور على الملف: حفظ متصفحك adb-bridge.py في مكان غير التنزيلات. غيّر ذلك الجزء من الأمر أو أعد تسمية ملف .txt.
  • «Something is already listening on port 5038»: هناك جسر آخر يعمل. أزل القديم (--uninstall أو uninstall.cmd) أو اختر منفذًا آخر باستخدام --port.
  • يعمل الجسر ولكن لا يظهر أي هاتف: يجب أن يرى خادم ADB الهاتف. شغّل adb devices وفعّل USB debugging واقبل رسالة «Allow USB debugging» على الهاتف.
  • «The bridge is running, but ADB is not installed»: ثبّت ADB بالأوامر الواردة في قسم هل لدي ADB؟ أعلاه (أو ثبّت Android Studio). تلاحظ الصفحة ذلك بنفسها بعد بضع ثوانٍ.
  • يطلب Chrome السماح بالوصول إلى الأجهزة على شبكتك: اسمح بذلك. بهذه الطريقة تصل الصفحة إلى الجسر على جهازك أنت.
  • يحظر برنامج مكافحة الفيروسات أو Windows المثبّت: يبني المثبّت برنامجًا صغيرًا فقط من شفرة مصدرية يمكنك قراءتها، ويكتب في مجلدات المستخدم الخاصة بك. اسمح به أو استخدم مسار Python.
