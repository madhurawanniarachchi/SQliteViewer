Android の SQLite データベースを表示

エミュレーター、デバッグビルド、または許可されたデバイスからエクスポートしたアプリのデータベースを開き、デスクトップのデータベースブラウザーをインストールせずに確認できます。

Android データベースを開く

まず、合法かつ安全にデータベースをエクスポート

SQLite Viewer は、すでにお持ちのファイルを開きます。スマートフォンからデータベースを抽出することはありません。確認する権限のあるデータベースを入手するには、Android Studio の Device Explorer、エミュレーター、アプリのバックアップ、または独自のデバッグツールを使用してください。

Android アプリのデータベースは、通常アプリ固有の databases ディレクトリにあり、拡張子が .db の場合も拡張子がない場合もあります。ブラウザのファイル選択に拡張子のないコピーが表示されない場合は、エクスポートしたファイルの名前を .db で終わるように変更してください。

アプリのスキーマを開いて確認

  1. エクスポートしたデータベースを SQLite Viewer にドロップします。
  2. デバッグ中の機能をテーブルのサイドバーで検索します。
  3. 関連しそうなテーブルを開き、最近の行を確認します。
  4. ER 図を使って、外部キーや Room スタイルの関係を把握します。
  5. 大きなイベントテーブルやキャッシュテーブルをスクロールする代わりに、的を絞った SQL を実行します。
SELECT *
FROM "sync_queue"
ORDER BY "created_at" DESC
LIMIT 0, 100;

デバッグアプリのデータベースを USB でライブ表示

デスクトップの Chrome または Edge で、ツールバーの Android を選び、USB デバッグを有効にしたスマートフォンを接続して、デバッグ可能なアプリを選びます。SQLite Viewer は run-as でデータベースをコピーし、最近の書き込みが含まれるようにライトアヘッドログをマージし、テスト中は数秒ごとに更新することもできます。すべてブラウザ内で完結します。リリースビルドは Android によって保護されており、この方法では読み取れません。

Android Studio は USB 接続を占有するため、ビューアには ADB サーバーモードもあります。Windows では、ワンクリックのブリッジインストーラーをダウンロードして、一度ダブルクリックします。サインインのたびに自動で起動する小さなヘルパーが設定され、ページは Android Studio と ADB サーバーを共有するため、両方を同時に使えます。macOS と Linux では、代わりに adb-bridge.py ヘルパーを実行してください。ページはブリッジを自動的に検出します。詳しくは ADB ブリッジのセットアップガイドをご覧ください。

アプリを再起動せずにデータを変更したいですか？ デバッグ専用の小さなヘルパーを追加し、ライブ編集のセットアップガイドに従ってください。

WAL データベースを正しく扱う

SQLite は先行書き込みログを使うことがあり、-wal と -shm の付随ファイルが生成されます。アプリが書き込み中にメインのデータベースだけをコピーすると、直近のトランザクションが欠落することがあります。データベースを閉じた状態、またはチェックポイント後に作成した整合性のあるエクスポートを推奨します。

機密データ: アプリのデータベースには、個人情報、トークン、業務記録が含まれている場合があります。確認する権限のあるファイルだけを使用し、デバッグが終わったらエクスポートしたコピーを削除してください。

Android データベースの編集

コピーを編集してダウンロードできますが、アプリのデータベースを置き換えると、スキーマの前提に反したりアプリの状態を壊したりする可能性があります。元のファイルを保管し、制約を検証し、可能な限りサポートされているマイグレーションやデバッグツールを使ってください。
