SQLite クエリガイド

SQLite データベースを調べるのに役立つクエリ

テーブル、インデックス、関係、データ品質を理解したいときは、安全で的を絞った SQL から始めましょう。

SQL ワークスペースを開く

ユーザーのテーブルとビューを一覧表示

SELECT type, name, sql
FROM sqlite_master
WHERE type IN ('table', 'view')
  AND name NOT LIKE 'sqlite_%'
ORDER BY type, name;

テーブルの列を確認

PRAGMA table_info('orders');

各列の宣言された型、NULL 可否、デフォルト値、主キー内の位置を返します。

外部キーを確認

PRAGMA foreign_key_list('orders');
PRAGMA foreign_key_check;

最初の文は、1 つのテーブルの宣言された参照を示します。2 つ目の文は、有効な外部キーの関係に違反している行を報告します。

重複する値を探す

SELECT email, COUNT(*) AS occurrences
FROM customers
WHERE email IS NOT NULL
GROUP BY email
HAVING COUNT(*) > 1
ORDER BY occurrences DESC;

インデックスを確認

PRAGMA index_list('orders');

インデックス名が分かったら、PRAGMA index_info('index_name') でその列を確認します。

クエリの動作を確認

EXPLAIN QUERY PLAN
SELECT *
FROM orders
WHERE customer_id = 42
ORDER BY created_at DESC;

実行計画から、フルテーブルスキャンが行われているか、SQLite が適切なインデックスを使えるかが分かります。

安全な進め方: まず SELECT や PRAGMA による確認用クエリから始めます。UPDATE や DELETE の前に、同じ WHERE 条件で SELECT を実行し、データベースの元のコピーを保管してください。

大きなテーブルをページ送りする

SELECT *
FROM events
ORDER BY id
LIMIT 100 OFFSET 0;

非常に大きなテーブルを繰り返し移動する場合、WHERE id > ? ORDER BY id LIMIT 100 のようなキーセットページネーションは、非常に大きなオフセットより効率的なことがよくあります。
