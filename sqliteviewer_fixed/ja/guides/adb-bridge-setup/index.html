Android ライブデバッグ

ADB ブリッジをセットアップ（Android Studio と併用可）

小さなヘルパー 1 つで、SQLite Viewer と Android Studio が同時にスマートフォンを使えます。ダウンロードして、配置して、自動起動にすれば完了です。

ビューアを開く

ブリッジは必要？

多くの場合は不要です。SQLite Viewer は、何もインストールせずに USB 経由でスマートフォンと直接通信できます（Chrome または Edge の USB 直接モード）。ブリッジが必要なのは 1 つの場合だけです。Android Studio（または別の ADB ツール）がすでにスマートフォンを使っているときです。USB 接続を占有できるのは 1 つのプログラムだけなので、ブリッジを使うと SQLite Viewer が Android Studio の ADB サーバーを共有できます。これで両方を同時に使えます。

Windows: ワンクリックインストーラー

  1. インストーラーをダウンロードします。 SQLite Viewer で Live Android を開き、ADB サーバーを選んでインストーラーをダウンロード (Windows) をクリックします。
  2. ファイルを保持します。 Chrome がファイルを確認できないと表示することがあります。保持（または未確認のファイルをダウンロード）を選んでください。ファイルはプレーンテキストなので、メモ帳で開いて、何をするのか正確に確認できます。
  3. 一度だけ実行します。 Install-ADB-Bridge.cmd をダブルクリックします。Windows に Windows によって PC が保護されましたと表示されたら、詳細情報、続けて実行をクリックします。
  4. ページに戻ります。 インストーラーが PC 上でブリッジを構築し、サインインのたびに自動起動するよう設定して、起動します。SQLite Viewer は数秒で検出します。ブリッジ経由で接続をクリックします。

ブリッジは %LOCALAPPDATA%\SQLiteViewerBridge にインストールされ、スタートアップフォルダーのショートカットがサインイン時に起動します。削除するには、そのフォルダーの uninstall.cmd を実行します。

どのシステムでも: Python でセットアップ

  1. Python 3 をインストールします。 python.org からダウンロードします。Windows では、インストーラーで Add Python to PATH にチェックを入れてください。ほとんどの Linux にはすでに python3 があります。macOS には標準では含まれていません。初めて python3 と入力すると、Apple のコマンドラインツールのインストールが提案されます（承諾してください）。または python.org のインストーラーも使えます。
  2. ファイルをダウンロードします。 adb-bridge.py をダウンロードします。ブラウザは「ダウンロード」フォルダーに保存します。末尾が .txt の場合は adb-bridge.py に名前を変更してください。
  3. 恒久的な場所にコピーします。 ターミナルを開き（どのフォルダーでも構いません。コマンドはフルパスを使います）、お使いのシステム用のコマンドを実行します。フォルダーを作成し、ファイルをコピーします。ブラウザが「ダウンロード」以外にファイルを保存した場合は、コマンドのその部分を変更してください。
  4. 自動起動にします。 お使いのシステム用のコマンドを実行します。コピーした場所のファイルについて、サインイン時に起動するエントリを設定し、ブリッジを今すぐ起動します。
  5. 接続します。 SQLite Viewer に戻ります。ブリッジは自動的に見つかります。ブリッジ経由で接続をクリックします。

手順 3: ファイルをコピー（一度だけ実行）

Windows（PowerShell。Windows キーを押し、powershell と入力して Enter）:

New-Item -ItemType Directory -Force "$env:LOCALAPPDATA\SQLiteViewerBridgePython" | Out-Null; Copy-Item "$env:USERPROFILE\Downloads\adb-bridge.py" "$env:LOCALAPPDATA\SQLiteViewerBridgePython\adb-bridge.py"

Windows（コマンドプロンプト。Windows キーを押し、cmd と入力して Enter）:

mkdir "%LOCALAPPDATA%\SQLiteViewerBridgePython" & copy "%USERPROFILE%\Downloads\adb-bridge.py" "%LOCALAPPDATA%\SQLiteViewerBridgePython\adb-bridge.py"

macOS（ターミナル）:

mkdir -p "$HOME/Library/Application Support/SQLiteViewerBridge" && cp "$HOME/Downloads/adb-bridge.py" "$HOME/Library/Application Support/SQLiteViewerBridge/adb-bridge.py"

Linux:

mkdir -p "$HOME/.local/share/sqliteviewer-bridge" && cp "$HOME/Downloads/adb-bridge.py" "$HOME/.local/share/sqliteviewer-bridge/adb-bridge.py"

手順 4: サインイン時に自動起動（一度だけ実行）

Windows (PowerShell):

python "$env:LOCALAPPDATA\SQLiteViewerBridgePython\adb-bridge.py" --add-to-startup

Windows（コマンドプロンプト）:

python "%LOCALAPPDATA%\SQLiteViewerBridgePython\adb-bridge.py" --add-to-startup

macOS:

python3 "$HOME/Library/Application Support/SQLiteViewerBridge/adb-bridge.py" --add-to-startup

Linux:

python3 "$HOME/.local/share/sqliteviewer-bridge/adb-bridge.py" --add-to-startup

Windows ではスタートアップフォルダーに非表示のショートカット、macOS では Launch Agent、Linux では systemd ユーザーサービス（またはデスクトップの自動起動エントリ）が作成されます。いずれも管理者権限は不要です。ファイルは今の場所に置いたままにしてください。移動した場合は、もう一度コマンドを実行します。

お急ぎですか？ 1 つのコマンドで手順 3 と 4 を実行

ファイルをダウンロードしたフォルダーでターミナルを開き、次を実行します。

python adb-bridge.py --install      # Windows
python3 adb-bridge.py --install     # macOS and Linux

スタートアップに手動で追加したい場合は？

Windows: Win + R を押し、shell:startup と入力して Enter を押します。開いたフォルダーで右クリックし、新規作成 → ショートカットを選び、場所を次のように設定します。

pythonw "%LOCALAPPDATA%\SQLiteViewerBridgePython\adb-bridge.py"

名前は SQLite Viewer ADB Bridge にします。python の代わりに pythonw を使うと黒いウィンドウが表示されません。サインアウトして再度サインインするか、ショートカットをダブルクリックして今すぐ起動します。

macOS: 上のコマンドは ~/Library/LaunchAgents/com.sqliteviewer.adbbridge.plist を作成します。Linux: ~/.config/systemd/user/sqliteviewer-bridge.service（または ~/.config/autostart/sqliteviewer-bridge.desktop）を作成します。これらのファイルを手書きすることもできますが、コマンドのほうが安全です。

確認、停止、削除

python adb-bridge.py --status                  # is it running?
python adb-bridge.py --remove-from-startup      # stop starting at sign-in (keeps the file)
python adb-bridge.py --uninstall                # stop it and delete everything
# add the full path to the file if you are not in its folder, as in the commands above

ADB はありますか？ なければインストール

ブリッジは ADB（Android Platform Tools）に中継します。Android Studio にはすでに含まれているため、Android Studio を使っている場合はこのセクションを飛ばせます。確認するには、ターミナルを開いて adb version を実行します。システムがコマンドを認識しない場合は、下のいずれかのコマンドで ADB をインストールしてください。ブリッジが動作しているのに ADB が見つからない場合は、SQLite Viewer が知らせます。ブリッジは PATH と、Android Studio、winget、Homebrew、手動ダウンロードの一般的なフォルダーから ADB を探すため、PATH を変更する必要はなく、ADB サーバーも自動で起動します。

Windows

最も簡単（Windows 10 と 11、PowerShell またはコマンドプロンプト）:

winget install --id Google.PlatformTools -e

winget がない場合は直接ダウンロード (PowerShell):

Invoke-WebRequest https://dl.google.com/android/repository/platform-tools-latest-windows.zip -OutFile "$env:TEMP\pt.zip"; Expand-Archive "$env:TEMP\pt.zip" "$env:LOCALAPPDATA\Android\Sdk" -Force; Remove-Item "$env:TEMP\pt.zip"

コマンドプロンプトでの同じ操作:

powershell -NoProfile -Command "Invoke-WebRequest https://dl.google.com/android/repository/platform-tools-latest-windows.zip -OutFile \"$env:TEMP\pt.zip\"; Expand-Archive \"$env:TEMP\pt.zip\" \"$env:LOCALAPPDATA\Android\Sdk\" -Force; Remove-Item \"$env:TEMP\pt.zip\""

うまくいったか確認 (PowerShell):

& "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe" version

macOS

Homebrew を使う場合:

brew install --cask android-platform-tools

Homebrew を使わない場合:

mkdir -p "$HOME/Library/Android/sdk" && curl -L -o /tmp/pt.zip https://dl.google.com/android/repository/platform-tools-latest-darwin.zip && unzip -o /tmp/pt.zip -d "$HOME/Library/Android/sdk" && rm /tmp/pt.zip

Linux

Debian、Ubuntu、Mint:

sudo apt install adb

Fedora:

sudo dnf install android-tools

Arch、Manjaro:

sudo pacman -S android-tools

その他のディストリビューション:

mkdir -p "$HOME/Android/Sdk" && curl -L -o /tmp/pt.zip https://dl.google.com/android/repository/platform-tools-latest-linux.zip && unzip -o /tmp/pt.zip -d "$HOME/Android/Sdk" && rm /tmp/pt.zip

次にスマートフォンを準備

  1. スマートフォンで設定 → 端末情報を開き、ビルド番号を 7 回タップします。
  2. 設定 → 開発者向けオプションを開き、USB デバッグをオンにします。
  3. スマートフォンを接続し、表示されたプロンプトで許可をタップします。adb devices を実行すると device として一覧に表示されるはずです。

何か設定する必要はありますか？

いいえ。 ブリッジは SQLite Viewer の Web サイトからの接続のみを受け付け、お使いのコンピューター上でのみ待ち受け (127.0.0.1)、同じコンピューター上の ADB サーバーにのみ中継します。ほかの場所に保存または送信されることはありません。

設定が必要なのは次の 2 つの場合だけです。

  • 別のアドレスから SQLite Viewer を使う場合（ご自身のコピー、または開発中の localhost）。同じコマンドでそのアドレスを許可します。
python "%LOCALAPPDATA%\SQLiteViewerBridgePython\adb-bridge.py" --add-to-startup --allow-origin https://your-address.example
  • ポート 5038 がすでに使用されている場合。 別のポートを使い、Android パネルの詳細設定に同じポートを入力します。
python "%LOCALAPPDATA%\SQLiteViewerBridgePython\adb-bridge.py" --add-to-startup --port 5040

許可したアドレスは、ブリッジと同じ場所にある origins.txt（1 行に 1 アドレス）に記録されます。Windows は %LOCALAPPDATA%\SQLiteViewerBridge（インストーラー）または %LOCALAPPDATA%\SQLiteViewerBridgePython (Python)、macOS は ~/Library/Application Support/SQLiteViewerBridge、Linux は ~/.local/share/sqliteviewer-bridge です。

トラブルシューティング

  • 「The bridge is not running on this computer」: インストーラーまたは上記のコマンドを実行するか、サインアウトして再度サインインします。その後、Android パネルを開き直します。
  • Python がありません: Windows では不要です。上のワンクリックインストーラーを使ってください。それ以外では python.org から Python 3 をインストールするか（Windows: Add Python to PATH にチェック）、macOS ではコマンドラインツールのインストール提案を承諾します。その後、コマンドをもう一度実行してください。
  • python が認識されない、または Microsoft Store が開く (Windows): Python がまだインストールされていないか、PATH のオプションを見落としています。python.org からインストールするか、コマンドの python を py に置き換えてください。設定 → アプリ → アプリの詳細設定 → アプリ実行エイリアスで Store のショートカットをオフにすることもできます。
  • コピーのコマンドでファイルが見つからないと表示される: ブラウザが adb-bridge.py を「ダウンロード」以外に保存しました。コマンドのその部分を変更するか、.txt ファイルの名前を変更してください。
  • 「Something is already listening on port 5038」: 別のブリッジが動作しています。古いものを削除する（--uninstall または uninstall.cmd）か、--port で別のポートを選んでください。
  • ブリッジは動作しているがスマートフォンが表示されない: ADB サーバーがスマートフォンを認識している必要があります。adb devices を実行し、USB デバッグをオンにして、スマートフォンの「USB デバッグを許可しますか？」のプロンプトを承認してください。
  • 「The bridge is running, but ADB is not installed」: 上のADB はありますか？のコマンドで ADB をインストールしてください（または Android Studio をインストール）。数秒後にページが自動的に検出します。
  • Chrome がネットワーク上のデバイスへのアクセス許可を求める: 許可してください。これは、ページがお使いのコンピューター上のブリッジに接続する仕組みです。
  • ウイルス対策ソフトまたは Windows がインストーラーをブロックする: インストーラーは、読めるソースから小さなプログラムをビルドし、ご自身のユーザーフォルダーに書き込むだけです。許可するか、代わりに Python の方法を使ってください。
